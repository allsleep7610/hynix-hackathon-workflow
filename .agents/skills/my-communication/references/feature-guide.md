# 기능안내 모드

완성된 기능을 사용자가 이해하고 활용할 수 있도록 실제 구현·검증 결과에서 설명할 요소를 추출한다. 실행 담당이 해당 기능 범위의 독립 R6 통과 결과를 받아 기본 안내를 연결할 때 읽는다. 질문 응답·재설명·자기 설명 연습은 이 모드의 고유 책임이 아니며 본문의 공통 소통 기준과 사용자 요청을 따른다.

## 근거와 범위

통과한 판본과 범위에 맞춰 관련 코드·실제 입력·처리 규칙·출력·유효한 검증 근거를 필요한 만큼 확인한다. 전달된 자료가 부족하면 구현에 없는 동작을 추정해 채우지 않고 설명할 수 있는 범위와 남은 미확인을 구별한다. 일부 범위의 통과를 기능 전체나 프로젝트 전체의 완료로 확대하지 않는다. 자체 점검을 독립 R6 판정으로 바꾸지 않는다.

기능 변화, 핵심 동작, 필요한 선택 이유, 사용 방법, 검증 범위·한계를 추출한다. 실제 입력이 처리 규칙을 거쳐 어떤 결과가 되는지 연결하고 중요한 선택 이유는 해당 동작 곁에 둔다. 파일·함수·용어는 이해와 사용에 필요한 만큼만 제시하며, 설명용 가상 예시와 실제 관찰을 구별한다. R6 상세 판정표나 명령·로그 전체를 반복하지 않는다.

## 출력 템플릿 — 사용자 취향

각 설명 문단은 첫 문장에 요지를 두고 뒤에서 필요한 내용을 풀어준다. 문장·문단 수는 기능 규모와 친숙도에 맞추며 다음 순서를 유지한다. 출력 구획명과 사용 방법의 `해야 할 일`, `주의 사항`, `완료 시그널` 표시는 템플릿대로 쓴다. 해당하는 조건이 없는 주의 사항만 생략할 수 있고, 정상 사용을 구별할 결과가 있으면 완료 시그널을 명시한다.

```text
사용할 수 있게 된 기능

[이제 무엇을 할 수 있는지 핵심 한 문장].
[이전과 달라진 사용자 경험을 설명합니다.]


핵심 동작

[대표 입력이 어떤 처리를 거쳐 어떤 결과가 되는지].
[이해에 필요한 규칙과 중요한 선택 이유를
해당 동작에 연결해 설명합니다.]


사용 방법

해야 할 일: [실제 위치와 필요한 조작을 간단하게].
주의 사항: [사용 결과에 영향을 주는 조건이 있을 때].
완료 시그널: [어떤 결과가 보이면 정상적으로 사용한 것인지].


검증 범위·한계

[어떤 범위의 동작을 확인했는지 핵심 한 문장].
[사용에 영향을 주는 미확인·제약이 있으면 설명합니다.]
```

사용 방법은 본문의 행동 안내 기준을 따른다. 실제 접속 위치나 결과 파일과 필요한 조작·입력·기대 결과를 연결한다. 선택적인 직접 사용은 사용자 응답을 기다리는 필수 관문으로 만들지 않는다. 완료 시그널은 정상 사용을 알아볼 표시이며 사용자의 이해도나 구현 검증 완료를 뜻하지 않는다.

## 책임 경계

**사용자 선택 — 검증 책임:** R5 등 실행 담당이 필요한 테스트, 사람만 가능한 필수 확인의 시점, 증거와 상태 갱신을 맡는다. 사용자 할 일을 만들거나 안내를 제공하기 위해 실행자가 수행 가능한 테스트를 생략·축소·이전하지 않는다. 사람만 가능한 필수 선행 확인을 기본 안내 시점 이후로 미루지 않으며, 필요한 조작은 공통 행동 안내로 설명한다.

R6가 보완·재정렬을 판정했으면 완성된 기능으로 안내하지 않고 담당 단계의 수정·재판정·방향 판단을 따른다. 유효한 AI 검증은 사용자가 직접 써보지 않아도 유지한다. 사용자 보고는 그 출처·범위대로 전달하고 AI의 직접 관찰로 바꾸지 않는다. 구현·입력·환경이 바뀌면 영향받는 근거의 유효성을 실행 담당이 확인한다.

**사용자 선택 — 안내와 이해 구분:** 설명 제공을 사용자의 이해·사용 완료로 단정하지 않는다. 별도 이해도 점수·문답 기록·확인 원장을 기본으로 만들지 않으며 안내·피드백은 새 실행 권한이나 독립 R6 통과를 만들지 않는다. 이미 승인된 독립 작업은 선택적인 안내 응답을 기다리는 이유로 멈추지 않는다.

시험·평가 환경에서는 해당 환경의 설명·코칭 제한을 먼저 적용한다. 규정상 중단해야 하는 안내를 모드나 호출명을 바꿔 재개하지 않는다. 시험별 단계 판단과 제한은 해당 시험 규정 담당에 유지한다.
