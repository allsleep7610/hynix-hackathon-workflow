# Design Feedback

사용자 피드백을 짧은 취향 문장으로 평평하게 만들지 않는다. 재사용할 가치가 있을 때 다음 구조로 추출한다.

1. **사용자 표현:** 원문 또는 의미를 보존한 짧은 문장
2. **보려던 것:** 화면에서 주목하려던 대상
3. **판단하려던 질문:** 비교, 결정, 확인 또는 이해하려던 일
4. **문제가 된 구조:** 위계, 배치, 데이터 표현 또는 상호작용의 실패
5. **일회성 요소:** 특정 데이터, 임시 오류, 한 번의 구현 사고처럼 일반화하면 안 되는 것
6. **재사용 가능한 판단 과정:** 다음 화면에서도 적용할 수 있는 시선과 사고 순서
7. **원칙 후보:** 적용 범위가 좁고 명확한 문장
8. **품질 검사:** 미래 결과가 통과해야 하는 구체적인 확인 항목

## 후보와 승격 기준

일회성 조정을 지속 기준으로 오인하지 않도록 현재 화면 반영과 원칙 저장을 분리한다. 다음 근거는 지속 원칙 후보를 제안할 이유이며, 사용자 확정 전에는 저장·승격하지 않는다.

- 사용자가 명시적으로 원칙이라고 확정함
- 여러 화면에서 같은 피드백이 반복됨
- 탐색, 위계, 상태, 신뢰, 접근성 또는 판단 흐름을 바꿈
- 앞으로의 AI 결과에 적용할 품질 검사를 만듦

두께, 간격, 투명도나 한 문장 표현만 바꾸는 피드백은 해당 결과의 조정으로 남긴다. 외부 사례는 사용자 피드백을 덮어쓰지 않는다. 반복·구조 영향·품질 검사 가능성은 후보의 근거이고 저장 승인이 아니다. 사용자가 지속 원칙으로 확정한 뒤 해당 범위에서 저장하며, 이미 확정·승인한 동일 범위를 다시 묻지 않는다.

승격할 때는 `user-principles.md`에 stable id, 적용 범위, 사용자 표현 또는 반복 근거, 원칙, 제외 범위와 품질 검사를 기록한다. 다음 디자인 작업은 이 파일을 먼저 읽어 관련 항목만 적용한다.
