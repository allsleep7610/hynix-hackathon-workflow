# Design Quality Check

요청에 해당하는 항목만 확인하되, 실제 화면을 만들었다면 표시와 상호작용 검증을 생략하지 않는다.

## 판단과 구조

- 사용자가 보려는 것과 판단하려는 질문이 첫 화면에 드러나는가
- 주요 행동과 보조 행동의 위계가 구분되는가
- 정보가 사용자 사고 순서대로 배치됐는가
- 사용자 취향(UDP-06) 검사: 구현 전 요구사항·기존 요소를 압축하고 요구 추가 시 전체 구조를 다시 정리했는가. 같은 의미·용도의 정보와 설명·출처·주의·상태가 한 화면에서 반복되지 않는가
- 비교 화면이면 기준, 기간, 데이터 범위와 필터가 같고 값이나 변화가 기억에 의존하지 않게 가까이 보이는가
- 위험, 비용과 되돌릴 수 없는 결과가 행동 가까이에 보이는가

## 상태와 기능

- 필요한 기본·로딩·빈 상태·오류·완료·비활성 상태가 있는가
- control 종류가 행동 의미에 맞는가
- 반복 workflow가 불필요한 이동과 입력을 요구하지 않는가
- 익숙하지 않은 아이콘에 설명이 있는가
- 대표 사용 장면에서 핵심 정보를 찾아 원하는 판단·행동으로 이어갈 수 있으며, 압축 과정에서 필요한 기능·의미가 사라지지 않았는가

## 화면 품질

- 모바일과 데스크톱에서 겹침, 잘림, 가로 넘침이 없는가
- 텍스트가 container와 용도에 맞는 크기인가
- 동적 내용과 hover가 레이아웃을 흔들지 않는가
- 대비, focus, keyboard, hit target과 motion 완화가 필요한 수준으로 확인됐는가
- 장식이 핵심 정보와 실제 대상을 가리지 않는가

## 근거와 학습

- 사실, 외부 근거, 추정과 취향을 구분했는가
- 선례에서 가져온 구조·세부와 어레인지할 차이를 현재 목적·조건으로 설명했는가
- 사용자 취향(UDP-03) 검사: 새 화면·큰 개편은 구현 전에 실제 선례 화면과 활용안을 보여주고 기반 선택을 확인했는가. 이미 확정한 범위는 재사용했는가
- 디자인이 지정한 조사 상세를 충분히 확보했으며, 미확인 화면·동작을 관찰 사실처럼 구현 근거로 삼지 않았는가
- 단일 사례를 일반 원칙으로 과장하지 않았는가
- 새 사용자 피드백이 일회성 조정인지 지속 원칙 후보인지 구분했는가
- 지속 원칙 저장은 사용자 확정 범위에만 한정했는가

## 구현 검증

선례를 활용한 화면은 가져오려던 장점이 결과에서도 보존됐는지 확인한다. 현재 작업에서 정한 기준으로 원본과 비교 가능한 조건·방법을 선택해 대조하고, 의도한 변형과 장점의 의도치 않은 손실을 구별한다. 대조가 어려운 부분과 확인 범위의 한계는 남긴다. 비교 방법을 고를 때 사례가 필요하면 [화면 활용 경험과 대조 예시](../../my-precedent-research/references/screen-detail.md)를 참고한다. 도구별 절차는 해당 도구 지침을 따른다.

사용자 취향(UDP-03) 검사: 사용자가 선택한 원본, 재구현한 기반 상태, 변형 결과를 대조할 근거가 있는지 확인한다.

대표 데이터로 사용 과제를 수행해 무엇을 먼저 보고 어떤 비교·판단을 거쳐 행동하는지 확인한다. AI의 과제 점검과 실제 사용자의 이해 확인을 구분하며, 표시·기능 통과만으로 이해 개선이나 실사용 효과를 입증했다고 보고하지 않는다.

공통 UI의 변경은 여러 화면에 영향을 줄 수 있으므로, 변경한 공통 요소·배치값을 사용하는 다른 화면도 검수 범위에 포함한다. 변경 전 기능과 이 범위의 핵심 사용 시나리오를 기록하고, 변경 후 같은 조건으로 다시 실행해 의도하지 않은 기능 손실이 없는지 확인한다. 실제로 검사한 화면·상태·viewport를 남겨 한 화면의 통과를 다른 화면의 정상으로 확대하지 않는다.

실제 UI를 구현했다면 가능한 환경에서 화면을 열고 대표 desktop/mobile viewport를 확인한다. 콘솔 오류, 빈 canvas, 깨진 asset, 겹침, 잘림과 주요 상호작용을 검사하고 확인하지 못한 항목을 남긴다.

사용자 취향: 모바일 관련 서비스를 만들 때는 별도 검수 요청을 기다리지 않고 모바일 버전도 웹 브라우저에서 직접 검사한다. 모바일 viewport 또는 모바일 에뮬레이션에서 화면 표시와 핵심 사용 흐름을 실행하며, 화면 크기만 줄인 정적 확인으로 끝내지 않는다. 현재 작업에 필요한 검사 방법은 AI가 선택한다. 브라우저에서 확인한 결과와 실물 기기에서만 확인할 수 있는 사항은 구분해 보고한다.
