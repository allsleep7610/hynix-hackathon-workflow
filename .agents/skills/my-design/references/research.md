# Design Research

외부 사례는 디자인을 대신 결정하는 정답이 아니라 현재 판단을 검증하거나 넓히는 근거다.

## 공통 조사 규격으로 연결

선례 탐색과 근거 확인은 my-precedent-research의 공통 조사 규격을 사용한다. my-design이 현재 화면의 조사 질문·범위·필요 상세를 지정하고, 결과를 받아 활용안·사용자 선택·구현·대조를 맡는다. 공통 조사 Skill에 디자인 선택이나 구현을 맡기지 않는다. 구체화 예시가 필요할 때만 [화면 활용 경험과 대조 예시](../../my-precedent-research/references/screen-detail.md)를 읽는다. 같은 자료나 공통 절차를 중복 조사·유지하지 않는다.

서비스 조사 후보는 선례조사 참조의 관련 구획에서 가져오고, 회사명이 아니라 확인한 기반·활용 조건으로 이번 화면의 선택에 연결한다. 조사에서 정리한 장점은 사용자 취향으로 확정하지 않는다. 내부·외부 분석의 설명과 실제 화면·흐름의 근거가 다르면 필요한 부분을 확인한다.

현재 화면에 옮길 이유와 적용 조건, 필요한 대안·반례를 설계 판단에 연결한다. 실제 적용할 근거와 변경 이유, 결과 확인 기준을 구현 인계까지 보존한다. 아래는 디자인의 근거 강도와 실험 해석 기준이다.

사용 가능한 경우 Lazyweb, 공식 디자인 가이드, 실제 제품 화면, 공개 실험 자료와 웹 조사를 활용한다. 특정 서비스에 연결할 수 없으면 조사를 중단하지 말고 다른 공개 근거를 사용하거나 근거 공백을 표시한다.

## 디자인에서 지정할 조사 상세

현재 화면을 재구현하는 데 필요한 상세를 골라 조사 요청으로 만든다. 모든 작업에서 같은 관찰 목록을 채우도록 요구하지 않는다.

- 사용자 과제와 가까운 서비스의 실제 화면 이미지·출처, 필요한 사용 흐름과 표시 상태
- 가져올 영역의 배치·크기·정렬·정보 위계와 정보량을 조절하는 방식
- 기간·항목 선택, 탐색, 펼치기 등 주요 조작에 따른 연동과 상태 변화
- 재사용할 수 있는 구현 기반과 적용 조건, 현재 목적과의 차이·한계

화면을 가져올 때는 실제 화면을, 동작을 가져올 때는 해당 흐름이나 확인 가능한 데모를 근거로 확보한다. 회사명·일반 디자인 원칙·제품 소개만으로 구현 기반을 확정하지 않는다. 접근하지 못한 화면·상태는 미확인으로 남기고 대체 근거를 조사한다. 재현에 필요한 근거 공백을 임의의 화면으로 채워 구현하지 않는다.

## 선례 제시와 구현 연결 — 사용자 취향(UDP-03)

사용자가 실제 화면을 구현 기반으로 선택하고 그 위에서 변형하기 위한 절차다. 선호와 적용 범위는 user-principles.md의 UDP-03에서 확인한다.

my-design은 조사 결과에서 비교할 후보를 골라 실제 화면을 시각적으로 보여준다. 출처와 해당 구역을 연결하고, 가져올 구조·동작, 유지·변경할 부분과 이유를 표시한다. 여러 선례를 조합하면 주된 기반과 보조 요소를 구분하고 추천안을 제시한다. 사용자 선택 시점과 반복 확인의 경계는 SKILL.md의 작업 흐름을 따른다.

선택한 기반은 필요한 범위까지 재구현한 뒤 목적에 맞게 변형한다. 원본과 기반 상태, 결과에서 무엇을 비교할지 구현 인계에 포함한다. 화면·흐름 대조는 현재 목적과 같은 성질을 비교할 수 있는 조건에서 수행하며, 단순한 참고 링크 제공을 결과 대조로 처리하지 않는다.

## 근거 강도

- **측정됨:** 실제 수치와 실험 조건이 확인됨
- **방향성:** 전후 화면이나 반복 사례는 있으나 성과 수치는 없음
- **단일 사례:** 한 제품 또는 맥락이 다른 사례
- **추정:** 직접 근거 없이 현재 화면에서 도출한 가설

측정 근거가 없으면 성과가 더 좋다고 단정하지 않는다. 검색 결과가 없다는 주장에는 검색 범위와 가장 가까운 사례를 함께 남긴다.

실험이나 성과 근거를 사용하면 가능한 범위에서 다음을 함께 기록한다.

- 출처와 확인 날짜
- 대상 화면과 변경 내용
- 지표 이름과 방향
- 표본, 기간과 비교 조건
- 실제 측정값인지 방향성 관찰인지
- 현재 작업에 적용할 수 없는 차이

## 가져올 것

- 사용자의 시선과 행동을 돕는 구조
- 상태와 위험을 드러내는 방식
- 반복되는 상호작용 관습
- 적용 조건과 실패 조건
- 접근성, 신뢰, 오류 방지 근거

가져오려는 장점을 재현하는 데 필요한 상세는 해당 근거에서 확인해 활용한다. 추상 원칙으로 요약했다는 이유만으로 실제 적용을 위한 조사가 충분하다고 판단하지 않는다.

## 버릴 것

- 회사 이름만으로 정당화한 스타일
- 현재 목표·조건으로 설명되지 않는 모사와, 이용 조건이 맞지 않는 고유 asset의 사용
- 출처 없는 수치와 성과 주장
- 현재 제품과 맥락이 다른데 억지로 적용한 패턴
- 긴 HTML 보고서 형식과 특정 외부 서비스의 설치·결제·잠금 화면 규칙
