# 기능 안내

사용자가 완성된 기능을 이해하고 활용하도록 돕는다. 실제 구현과 유효한 실행 근거를 읽어 설명하며, 진행·검증 책임과 사용자 이해를 구분한다.

## 호출 시점과 설명할 내용

**사용자 선택 — 기본 안내:** 핵심 기능이 해당 범위의 독립 R6를 통과한 뒤 메인 에이전트가 안내한다. 통과한 판본·범위를 기준으로 설명하며, 일부 범위의 통과를 기능 전체나 프로젝트 전체의 완료로 확대하지 않는다. R6가 보완·재정렬을 판정했으면 수정·재판정 또는 필요한 방향 판단으로 연결하고 완성된 기능으로 안내하지 않는다.

작업 중 기능 질문·명시적 안내 요청에는 현재 관련 코드·입력·출력·유효한 검증 결과를 필요한 만큼 확인해 바로 설명한다. R6가 미완료이거나 독립 평가가 불가능하면 자체 검증 결과와 구분한다. 질문에 필요한 부분에 집중하며 모든 단계나 작은 변경마다 전체 설명을 반복하지 않는다.

입력에서 어떤 규칙과 처리를 거쳐 결과가 나오는지, 어떻게 사용하는지, 중요한 선택 이유와 한계를 실제 근거에 연결한다. 파일·함수·용어는 이해에 도움이 되는 만큼만 제시한다. 아직 구현하지 않았거나 검증하지 못한 동작은 현재 확인한 기능과 구별한다.

**출력 형식 — 사용자 선택:** 기본 안내는 **사용할 수 있게 된 기능 → 핵심 동작 → 사용 방법 → 검증 범위·한계** 순서로 설명한다. 실제 입력 하나가 처리 규칙을 거쳐 어떤 결과가 되는지 연결하고, 중요한 선택 이유는 관련 동작 곁에 둔다. 규모에 맞게 항목을 짧은 문단으로 합칠 수 있으며, R6의 상세 판정표나 명령·로그 전체를 반복하지 않는다. 특정 질문에는 관련 답·규칙·필요한 예시만 제시한다.

사용자의 자기 설명·질문 연습은 요청하거나 원할 때만 돕는다. 설명했다는 이유로 이해 완료를 단정하거나 이해도 점수·문답 기록을 기본으로 만들지 않는다.

## 검증 책임과 직접 사용 안내

**사용자 선택 — 검증 책임:** 명세와 변경 영향에 필요한 검증은 실행자가 수행한다. 사용자 할 일을 만들거나 안내를 제공하기 위해 수행 가능한 테스트를 생략·축소·이전하지 않는다. 검증이 남아 있으면 기존 작업 흐름에서 수행하며, 기능 설명을 검증 완료 근거로 쓰지 않는다.

사용자가 원하거나 이해·활용에 도움이 되면 직접 사용해 볼 방법을 안내한다. 실제 접속 위치 또는 결과 파일, 조작·입력과 기대 결과를 현재 구현에 맞게 제시한다. 선택적 사용 안내 때문에 사용자의 응답을 기다리는 필수 관문을 만들지 않으며, 독립된 승인 작업은 계속한다.

규정·도구 제한이나 명세상 사용자만 확인할 수 있는 필수 항목은 R6 전에 필요하면 이유·조작·확인 범위·기대 결과를 안내하고 실제 확인 전까지 해당 항목을 미확인으로 둔다. 기본 안내 시점 때문에 선행 확인을 뒤로 미루지 않는다. 이를 위해 수행 가능한 다른 검증을 생략하지 않는다. 시험 화면의 자동 조작이나 제한 우회는 하지 않는다.

유효한 AI 검증 결과는 사용자가 직접 써보지 않아도 유지한다. 사용자가 실제 관찰을 알려주면 그 출처와 범위만 기존 작업 기록에 연결하고, AI의 직접 관찰로 바꾸거나 다른 동작까지 확인했다고 확대하지 않는다. 관련 구현·입력·환경이 바뀌면 영향받는 근거의 유효성을 다시 살핀다. 별도 확인 원장이나 중복 검증표는 기본으로 만들지 않는다.

## 기존 작업과 시험 단계

R5는 다음 실행과 기존 상태 갱신을, R6는 독립 판정을 맡는다. 이 Skill의 설명·안내·사용자 피드백은 새 실행 권한이나 독립 R6 통과를 만들지 않는다.

하이닉스 시험에서 제출물 확정 뒤 후속 서술형 단계에는 설명·답변 생성·첨삭·코칭을 중단한다. 단계가 불명확하고 실제 평가 문항으로 보이면 먼저 단계를 확인한다. 최신 규정과 필요한 참조는 기존 hynix-exam-guide를 따른다.

[제작 배경](references/design-context.md)은 만든 니즈·선례·변형 이유를 검토할 때 읽는 기록이며 실행 지침이 아니다.
