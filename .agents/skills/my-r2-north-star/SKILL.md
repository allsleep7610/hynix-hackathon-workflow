# R2 — 북극성 목표

**R1에서 이해한 문제를 바탕으로 이번 세션이 도달할 상태와 맡을 범위를 합의한다.** 사용자 가치·우선순위와 표면 요청이 해결하려는 더 높은 층위의 필요를 읽어 목표 후보를 제안한다. 사용자가 자신의 니즈와 이번 세션의 크기에 맞게 후보를 조율·분할하도록 하며, 상위 필요를 발견한 것만으로 작업 범위를 확대하지 않는다. 문제의 재탐색은 R1, 구체적인 실행 계약은 R3에 연결한다.

- 단편적 요청은 요청에 담긴 목표를 짧게 확인하고 R3로 넘긴다. 별도 목표안과 반복 확인 질문을 만들지 않는다.
- 여러 행동·대화·중요한 선택이 이어질 작업은 상위 목적과 이번 세션에서 맡을 몫을 구분하고, 세션 용도, 목표 문장, 달성 상태, 범위, 아직 정하지 않는 것을 사용자 검토 가능한 크기로 제시한다. 사용자가 확인한 뒤 고정한다.
- 사용자가 R2를 직접 요청하면 명시적인 목표안 작성·확인으로 들어간다. 이미 정확한 목표를 제시하고 확정까지 지시했다면 같은 문장을 다시 승인받지 않는다.
- 이미 확정된 목표 안의 후속 작업은 그 목표를 사용한다. 목표·달성 상태·범위를 바꾸려면 이유와 영향을 설명하고 사용자 확인을 받는다. 문제 이해 자체가 달라졌다면 R1로 돌아갈 필요성을 먼저 제시한다.


## 출력 형식 — 사용자 선택

여러 단계의 작업과 명시적인 R2에는 아래 순서를 적용한다. 각 항목은 핵심 문장을 먼저 두고 맥락과 이유를 연결하며, 단편적 요청의 짧은 통과와 기존 목표 재사용은 유지한다. 목표가 R1에서 벗어나지 않는지는 검토하되 그 연결 설명을 별도 필수 문장으로 반복하지 않는다.

**상위 목적**

**[이 문제를 해결해서 사용자가 얻으려는 더 큰 변화].**

[왜 중요한지 설명하고 이번 세션이 기여할 상위 목적을 보여준다. 그 전체를 이번에 해결한다고 약속하지 않는다.]

**이번 세션의 목표**

> **[이번 세션이 도달하려는 상태를 나타내는 목표 문장].**

[이번 세션의 역할과 상위 목적 중 어떤 몫을 맡는지 설명한다.]

**도달할 상태**

**[세션을 마칠 때 사용자가 활용하거나 판단할 수 있게 되는 상태].**

[어떤 결과로 무엇을 할 수 있는지와 여러 결과의 연결을 설명한다. 세부 검증 기준은 R3에서 구체화한다.]

**이번 세션의 범위**

**[이번에 어디까지 맡고 어디에서 마무리할지].**

[포함할 일과 이후로 넘길 일을 이유와 함께 설명한다. 외부 조건에 의존하면 이번에 책임질 부분과 성립 조건을 구분한다.]

**아직 정하지 않는 것**

**[목표 합의 뒤 다음 단계에서 구체화할 사항].**

[지금 정하지 않아도 되는 이유와 결정 시점을 설명한다. 목표나 범위를 바꿀 미확인은 목표 확정 전에 확인한다. 해당 사항이 없으면 없다고 적는다.]

확정한 R2 산출물 전체는 `my-session-save`의 SESSION R2 구획에 원문 그대로 보존한다. 단순 요청에 별도 목표안을 강제하지 않는다. R2의 목표 합의는 runtime Goal 생성, 구체 작업 실행, 외부 반영이나 배포 승인과 별개다. 다음 R3가 위치·범위·완료 기준·권한을 계약으로 정한다.
