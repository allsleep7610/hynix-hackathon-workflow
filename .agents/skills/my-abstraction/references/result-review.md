# 추상화 결과 검토 기준

사용자가 원리 추출·활용을 원하는 결과를 판정하거나, 사례 비교를 통해 지침을 보정할 때 읽는다. 스킬의 일반 응답마다 이 표를 출력하거나 별도 보고서를 요구하지 않는다.

## 요청 목적에 따른 판정

평가 대상은 실제 결과의 의미와 활용성이다. 요청에서 요구하지 않은 타 분야 전이나 상세 실행 계획을 새 완료 조건으로 만들지 않는다. 충분한 맥락이 주어졌다면 이를 활용했는지도 함께 본다.

| 판정 대상 | 충족을 뒷받침할 내용 | 보완이 필요한 경우 |
|---|---|---|
| 관계 구조 | 사례의 요소를 역할로 대응하고, 역할 사이의 방향·의존성·변화 관계가 연결되어 있다. 무엇이 달라지면 왜 다른 판단이 필요한지 읽힌다. | ‘협업이 중요하다’ 같은 표어, 특징 나열, 모든 명칭을 상위 단어로 바꾼 결과만 남는다. |
| 성립 조건과 한계 | 적용을 좌우하는 조건을 보존하고, 조건을 제거·변경하면 원리가 어디서 약해지거나 성립하지 않는지 설명한다. 관찰과 추론의 근거 수준을 구별한다. | ‘상황에 따라 다르다’ 또는 ‘가설이다’만 덧붙이거나, 원문에 없는 원인을 확정한다. |
| 재적용 | 요청 목적에 필요할 때, 같은 역할·관계를 대상 문제에 대응시키고 현재 무엇을 선택·확인·변형할지 제시한다. 구조가 대응하지 않는 부분과 미확인을 남긴다. | 유사한 사례 이름만 바꾸어 덧붙이거나, 원리와 관계없이 일반적인 조언을 제공한다. |
| 목적·수준·부담 | 사용자가 요청한 대상을 유지하며 남김·제거가 활용 목적에 연결된다. 필요한 구체성을 남기고 과잉 일반화나 불필요한 설명을 줄인다. | 간결하지만 판단할 정보가 없거나, 요청하지 않은 목표·산출물·긴 양식을 추가한다. |

형식은 고정하지 않는다. 짧은 문장이나 그림으로도 관계와 조건이 분명할 수 있다. 조건·반례·수준의 개수를 채우기보다, 이번 원리를 실제로 무너뜨릴 차이를 살펴본다. 모든 항목의 구획이나 특정 용어가 있다는 이유로 통과시키지 않는다.

## 비교 근거와 보정

입력·목적·주어진 맥락을 보존하고 비교한 판본과 실제 응답을 남긴다. 작성자가 기대한 결과를 평가용 입력에 추가해 얻은 응답과, 원래 요청 그대로 얻은 응답을 구별한다. 각 기준은 응답의 어느 설명으로 충족되는지 연결하고, 빠진 내용과 확인하지 못한 효과를 구별한다.

보완은 관찰한 문제와 연결되는 최소 변경으로 한다. 특정 사례의 정답을 일반 지침에 넣지 않는다. 보정한 부분은 영향을 받는 사례로 다시 확인하며, 한 사례를 잘 처리한 사실을 일반적 성능 우위나 사용자 만족으로 확대하지 않는다.
