# R4 — 실행 구조화

비결정론적인 AI 작업을 사용자가 이해할 실행 단위·의존관계·평가·담당·승인 범위·멈춤 지점으로 구조화한다. 사용자는 목표·가치·감수할 부담·새 권한을 판단하고, AI는 계약 안의 전문 방법·기술 보정을 맡는다. 중요한 선택의 이유와 한계는 설명하되 수행의 깊이를 사용자의 사전 지식에 한정하지 않는다. 같은 출력이나 무실패를 보장하는 구조는 아니다.

R3 계약의 목표·범위·완료 기준·핵심 가정·권한을 다시 정하거나 복제하지 않는다. 모든 작업에 최소한의 실행 구조를 만들되, 단순 작업은 내부에서 처리하고 별도 트리나 사용자 검토를 강제하지 않는다.

## 출력 구성과 대조

목록만 요청받으면 현재 목표·계약·확인된 정보로 구조를 제시하고, 추가 조사·계약 확정·실행으로 넘어가지 않는다. 목록에 영향을 주는 빈칸은 미확인으로 남긴다.

비단순 R4는 아래 순서의 트리를 사용한다. 현재 묶음은 실행할 절차까지 구체화하고 후속 단계는 목표 달성까지 이어질 결과·명세로 남긴다. 완료와 상태는 최신 사용자 정정·실제 근거에 맞춰 표시하고 사용자 보고는 출처를 밝힌다. 완료 결과나 선행 조건이 없으면 `없음`, 진행 여부를 모르면 상태 미확인, 실제 선행 조건에 막혔으면 대기로 표시한다.

의존관계는 `←` 뒤에 필요한 선행 결과·사용자 결정을 적는다. 독립 작업은 결과를 합쳐 쓸 때만 묶고, 묶음 표시를 병렬 실행·위임 승인으로 해석하지 않는다. 멈춤은 새로운 사용자 판단·권한이 필요한 행동 직전에 두며, 없으면 승인 범위의 다음 의미 있는 판단 지점 또는 목표 달성까지 이어간다. 이미 승인된 판단을 다시 묻지 않는다.

**출력 형식 — 사용자 취향:** 단계 헤더에 기존 세션 진행 또는 세션 분기와 제안·합의·진행·완료 중 확인된 상태를 표시한다. 서브에이전트는 맡길 작업 옆에만 `[서브에이전트 활용·확인된 상태]`로 표시하고 필요한 범위·돌려받을 결과를 적는다. 후속 진행 방식은 미정이면 생략하며, 분기 제언에는 기대 이점·인계 부담·메인의 통합 역할을 연결한다. 조건부 항목은 해당할 때만 표시하고, 형식을 채우려고 작업·승인·위임을 만들지 않는다.

```text
[세션 목표] — 현재: [이번 묶음] · 확인된 완료: [결과/없음]
전체 흐름: [완료된 단계] → [이번 묶음] → [추상화한 후속 단계] → [목표 달성]

├─ [이번 단계·묶음] [진행할 세션·확인된 상태]
│  달성할 결과: [결과] ← [필수 선행 결과/없음]
│  ├─ [작업 A] ← [필요한 선행 결과/없음]
│  └─ [작업 B] ← [필요한 선행 결과/A와 서로 선행하지 않음]
│  결과 검토·통합: [담당·판정 기준·합친 결과]      (합칠 때만)
│  진행 시 멈춤: ◆ [미해결 사용자 판단·새 권한] 직전 /
│                없으면 [승인된 범위의 다음 판단 지점 또는 목표 달성]
└─ [후속 단계] [진행할 세션·확인된 상태]          (판단한 경우만 표시)
   ← [필요한 선행 결과]
   달성할 결과: [후속 결과·명세]

상태 미확인: [진행 여부를 모르는 결과]           (있을 때만)
```

반환 전 초안을 위 기준과 대조한다. 판단을 바꿀 직접 자료가 있으면 분석 필요성을 검토해 질문·자료·방법·평가 근거를 해당 실행 단위에 연결한다. 분석 권한이 없으면 선행 항목으로 남긴다. 자료가 있다는 이유만으로 전수 분석하지 않으며 판단에 영향을 주는 공백만 드러낸다.

## 실행 단위와 진행 방식

모든 작업은 실패 가능 원인과 결과를 판정할 기준에 따라 실행 단위를 나눈 뒤 의존관계로 순서를 정한다. 원인은 관찰 전에는 가설이다. 각 단위의 결과·평가 근거·선행 결과·수정 대상·담당·멈춤 지점을 연결하며, 단순 작업은 내부에서 짧게 처리한다. 기준은 R3의 원하는 변화와 완료 기준을 따른다. 서로 다른 실패를 구별하거나 결과를 따로 평가할 필요가 없는 작업까지 잘게 나누지 않는다. 별도 평가의 효용이 인계·검토 부담을 감당할 단위는 수행에 참여하지 않은 평가자의 R6 범위·입력·권한을 함께 정한다.

작업 단위와 의존관계를 정한 뒤 진행할 세션과 위임 필요를 판단한다. 각 작업의 독립성·별도 맥락 유지·사용자와 반복적으로 방향을 검토할 필요를 맥락 인계·중복 작업·결과 통합의 부담과 비교한다. 판단이 밀접하게 연결된 작업은 같은 세션에서 이어가고, 독립적으로 방향을 발전시킬 작업은 별도 세션을, 범위·산출물·완료 기준이 명확한 작업은 서브에이전트 위임을 검토한다. 세션 분기는 작업을 진행할 대화 공간이고 서브에이전트는 그 안에서 작업을 맡기는 방식이므로, 기존 세션과 분기 세션 모두 필요한 작업만 위임할 수 있다.

사용자 명시가 없어도 분기의 이점이 추가 관리 부담보다 크면 세션 분기를 제언한다. 필요한 선행 결과·공통 연결 규격이 미정이면 먼저 정리할 부분과 이후 분기할 부분을 구분해 제안한다. 맡길 역할·기대 이점과 인계·통합 부담을 설명하며 모든 작업에 분기나 방식 비교를 강제하지 않는다. 실제 세션 생성·분기는 사용자의 명시적 요청 또는 유효한 사전 승인 범위에서 수행한다. 작업 분리나 병렬 후보 표시는 그 자체로 서브에이전트 사용이나 실행 승인이 아니다. 사용자가 R4 실행 계획을 승인하면 그 범위 수행에 필요한 서브에이전트 등 내부 위임도 포함되며, 위임 자체의 반복 승인은 요구하지 않는다. 위임받은 작업도 원래 범위·제한을 따르고, 병렬 수행은 독립성·동일 파일과 공유 상태의 동시 수정 충돌을 확인한 뒤 정한다.

틀리면 작업이 무너지는 가정과 저비용 확인을 고비용 의존 작업보다 앞에 둔다. 작업 분해는 병렬 분기와 다르다. 선행 결과·공통 연결 규격이 확정되어 서로의 미완성 결과를 기다리거나 추측하지 않아도 수행 가능하고, 공유 파일·상태 충돌을 관리할 수 있는 단위만 병렬 후보로 둔다. 통합은 필요한 분기 결과가 나온 뒤 메인이 같은 기준으로 확인한다. 먼 미래의 절차까지 펼치거나 모든 작업에 같은 상태·판단 항목을 강제하지 않는다.

비단순 작업의 확정된 R4 전체는 시험 작업공간에서 정한 `SESSION.md`의 R4 구획 한 곳에 원문 그대로 보존한다. 다른 단계의 확정 원문도 같은 문서에서 유지한다. 조건 요약으로 대체하거나 승인 원장을 따로 만들지 않는다. 초안·검토 요청은 확정 상태와 구별한다. 실제 실행할 R4를 보존·갱신하거나 세션 분기를 인계할 때 [실행 맥락 연결](references/execution-context.md)을 읽는다. 시작·재개·맥락 압축 후 또는 원문이 누락·잘렸거나 상태가 충돌하면 필요한 SESSION을 직접 확인한다. 현재 완전한 최신 원문이 이미 문맥에 있으면 중복 조회하지 않는다. 파일 존재·편집·입력은 의미·완료·권한을 판정하지 않는다.

사용자 방향 판단이 필요한지와 실행 권한이 있는지는 별도로 판단한다. 현재 요청·유효한 사전 승인에 포함된 행동은 다시 묻지 않는다. 새 승인에 해당하는 정확한 대상·행동·조건만 `my-action-authority`로 확인한다.

분기 전에 [실행 맥락 연결](references/execution-context.md)의 최소 합의사항을 확인한다. 연결 조건과 작업공간 배치는 AI가 제언하고 사용자 검토·합의 후 분기한다. 분기 요청만으로 맡길 내용과 연결 조건까지 합의되었다고 해석하지 않는다. 기존 합의·승인은 재사용하고 새로 생기거나 달라진 사용자 판단만 확인한다. 분기 승인과 분기 후 작업의 실행 권한은 구분한다. 이는 각 세션의 가정과 수정 대상이 어긋나 통합 때 다시 결정하거나 다른 작업을 덮어쓰는 비용을 줄이기 위한 것이다.

위임이 실제로 필요하고 허용될 때 R4는 위임 범위·산출물·완료 기준·권한을 정한다. 서브에이전트의 모델·추론 강도는 별도로 지정하지 않고 현재 메인 작업의 설정을 계승한다.

실행 결과·증거만 부족하면 R5에서 같은 단위를 보완한다. 묶음·순서·의존관계가 틀리면 R4에서 영향받는 부분만 수정한다. 범위·완료 기준·권한·핵심 가정은 R3, 세션 목표는 R2, 문제 이해는 R1로 돌아갈 사유다. 계약 안의 기술 보정·순서 조정은 AI가 처리한다. 목표·범위·완료 기준·중요 가정·권한을 바꿔야 한다면 관찰된 사실, 미확인, 영향, 돌아갈 단계를 설명하고 사용자 확인을 받아 공식 복귀한다. 계속하면 손상이 커질 때는 먼저 안전하게 멈춘다. 유효한 결과·승인은 유지하며, 복귀 흐름 전체를 매번 출력하지 않고 변경 신호가 생길 때 필요한 경로만 알린다.

실행 승인을 포함하지 않은 구조 검토·합의만으로 작업을 시작하지 않는다. 실행 계획의 승인과 필요한 내부 위임 범위를 확인한 다음 단위는 R5로 넘긴다.
