# 전체 R4 보존·갱신과 세션 분기

확정한 R4를 실제 실행에 연결하거나 분기를 인계할 때 읽는다. 목적은 실행 에이전트가 전체 작업 구조와 현재 경계를 유지하도록 하는 것이다. 일반 목록 요청에 별도 저장·분기를 강제하지 않는다.

## 전체 정본

시험 작업공간에서 정한 `SESSION.md`의 R4 구획이 해당 세션의 전체 R4 정본이다. 같은 문서의 R1~R3 확정 원문도 실행 근거로 유지한다. 사용자가 검토한 산출물을 재요약하지 않고 그대로 보존한다. 이후 실제 결과에 따라 완료·현재 위치·남은 흐름과 영향받는 실행 구조를 갱신하되, 합의한 목표·계약·권한·사용자 멈춤 지점을 임의 변경하지 않는다. 현재 묶음은 구체적으로, 후속 흐름은 추상적으로 유지한다. 미채택 제안은 확정 내용과 구별한다. 이미 다른 파일에 전체 R4를 보존했다면 정본을 이 위치로 연결하고 이전 파일을 또 하나의 현행 정본으로 관리하지 않는다.

갱신은 [SESSION 규격](../../my-session-save/references/session-document.md)에 따라 읽은 버전·잠금을 확인하고 R4 구획 전체를 반영한 SESSION을 원자적으로 교체한다. 다른 구획 원문은 보존하고 현재 상태는 CURRENT에 둔다. 원본이 없거나 현재 요청·승인과 충돌하면 확인 가능한 맥락으로 복원하고 영향받는 실행 전에 부족한 판단을 확인한다. 이 구획 갱신으로 상위 단계 산출물을 임의 변경하지 않는다.

## 갱신·재입력

R5가 정한 1차 결과나 후속 의미 있는 결과에 도달하면 실제 결과·평가 근거를 확인하고 전체 R4를 갱신한다. R1~R4 확정·변경, 중요한 승인·조건 변경, 의미 있는 실행 단위 완료, 중단·인계 전에는 관련 상태와 확정 원문을 저장한다. 시작·재개·맥락 압축 후·합의 원문 누락/잘림·상태 충돌에는 필요한 SESSION을 조회한다. 현재 완전한 원문이 이미 문맥에 있으면 중복 조회하지 않으며 매 도구 호출·작은 진척마다 저장하지 않는다.

전달된 전체 SESSION 또는 변경 구획을 실제 결과·현재 요청·유효한 승인과 대조하고 다음 작업을 정한다. 전체 최신 입력을 확인했으면 중복 조회하지 않는다. 상위 기준이 바뀌면 영향받는 실행 전에 하위 구조의 유효성을 확인한다. 승인된 범위는 계속하고 사용자 판단·새 권한이 필요한 행동 직전에는 멈춘다. 파일 편집이나 Hook 실행이 새 권한을 만들지 않는다. 결과 확인 없이 상태만 완료로 바꾸지 않는다.

SESSION 규격 한 곳에서 원문·잠금·버전 대조·충돌 처리를 관리한다. 이 시험팩에는 Hook 설정·이벤트 runner·출력 캐시를 포함하지 않는다. 공통 진입 기준과 직접 조회는 모델 지침이며 이벤트 강제 실행이나 자동 복원을 보장하지 않는다.

전체 작업 맥락을 필요한 시점에 다시 확인하는 방향으로 구현한다. 자연 사용의 판단 개선·추가 입력 비용은 이후 실제 근거로 보정하며 효용 입증을 구현의 선행 조건으로 만들지 않는다.

## 분기와 통합

실패 가능 원인·평가 기준으로 단위를 나누고 의존관계를 정한 뒤 독립 단위만 분기 후보로 둔다. 예를 들어 데이터 규격·예제 확정 뒤 자료 처리와 화면 구현은 독립 수행할 수 있지만 실제 연결은 두 결과가 필요하다. 분해된 모든 작업을 별도 세션으로 만들지 않는다. 이 절의 분기 전 합의는 별도 사용자 세션에 적용하며, 서브에이전트 내부 위임은 R4 본문의 실행 승인 기준을 따른다.

### 분기 전 합의

기존 R3·R4와 현재 요청에서 다음 사항이 합의되어 있는지 확인한다. 각 항목은 해당 작업에 필요한 만큼 구체화한다.

- **역할과 결과:** 각 세션의 담당 범위·산출물·완료 기준과 필요한 평가 근거.
- **연결 조건:** 필요한 선행 결과·분기 간 의존관계·공통 연결 규격.
- **작업 경계:** 세션별 작업 경로·분리 방식·기준 코드·기존 미커밋 변경의 포함 여부와 처리, 수정 대상·공유 상태의 담당과 처리 순서·허용 행동·멈춤 지점.
- **인계와 통합:** 메인에 돌려줄 결과·근거·남은 문제, 통합 담당·대상·기준과 필요한 사용자 판단.

연결 조건과 작업공간 배치는 AI가 초안을 제언하고 사용자가 검토한 뒤 합의하여 확정한다. 무엇을 먼저 확보해야 하는지, 각 세션이 어떤 결과를 주고받고 어떻게 연결하는지, 어디에서 수정할지와 남은 미확인을 설명한다. 분기 요청만으로 이 검토·합의를 생략하지 않는다. 이미 검토·합의한 조건은 재사용하고 새로 생기거나 달라진 조건만 검토받는다. 세부 구현 방법은 합의한 연결 조건과 작업 경계 안에서 AI가 정한다.

합의와 분기 권한이 모두 확보되면 분기한다. 필요한 선행 결과·연결 규격이 부족하면 선행 작업이나 순차 수행 방안을 제언하고 필요한 사용자 판단을 확보한 뒤 구조를 조정한다. 합의된 범위·완료 기준·핵심 가정·권한을 바꿔야 하면 해당 단계에서 사용자 확인을 받는다.

### 작업공간과 인계

지원되는 분기 경로와 작업공간 분리 방식을 확인한다. 새 채팅이나 Git 브랜치만으로 파일이 격리되었다고 판단하지 않는다. 병렬 수정은 별도 워크트리·작업 폴더 등으로 수정 대상을 분리하고, 같은 작업공간을 사용해야 하면 읽기 전용·담당 분리·순차 처리로 같은 파일·상태의 동시 수정을 막는다. 도구가 별도 작업공간 생성에 명시적 요청을 요구하면 제안한 방식에 대한 승인도 확보한다.

분기 생성 후 파일 수정 전에 실제 작업 경로·저장소 또는 워크트리·기준 코드를 합의한 배치와 대조한다. 경로·기준이 다르거나 확인할 수 없으면 영향받는 수정을 멈추고 배치를 바로잡는다. 분기는 자기 담당 작업공간·수정 대상에서 작업하며 메인·다른 분기의 파일을 직접 덮어쓰지 않는다. 설치본·공통 데이터·외부 서비스 등 작업공간 밖의 공유 상태는 별도 워크트리로도 분리되지 않을 수 있으므로 합의한 담당과 순서를 따르고 새 권한을 추정하지 않는다.

분기에 전체 SESSION 정본의 위치·내용과 위 합의사항을 전달한다. 원본을 참조할 수 없으면 분기 시작에 전체 내용을 전달하되 전역 사용자 자산에 승격하지 않는다. 분기는 맡은 역할과 현재 상태를 구별하며 원본의 다른 담당 권한을 상속한 것으로 해석하지 않는다. 메시지·외부 행동·모델 변경 권한도 자동 생성하지 않는다. 모델·추론 강도는 본문의 계승 기준을 따른다.

분기는 자기 세션의 `SESSION.md`에 전달받은 R1~R4 전체 기준과 맡은 역할·현재 위치를 보존하고 메인의 통합 정본을 임의로 덮어쓰지 않는다. 실제 변경·산출물·평가 근거·남은 문제를 메인에 인계하면 메인이 원래 단위의 기준과 분기 간 연결을 확인해 통합하고 전체 R4를 갱신한다. 분기 완료나 개별 R6 통과는 아직 승인되지 않은 후속 작업의 권한이 아니다.
