# 응시 환경과 진행

사전 준비·체험·과제·제출 중 현재 필요한 절만 확인한다. 출처와 판본 관계는 [sources.md](sources.md)를 따른다.

## 사람이 준비할 사항

| 항목 | 확인할 내용 |
|---|---|
| 일정 | 2026년 10월 31일 토요일 10:00~14:00 일괄 응시이다. 일요일로 변경할 수 없다. |
| 접속 준비 | 09:40까지 접속하여 준비하고, 당일 09:40 추가 안내 메일을 확인한다. |
| 컴퓨터·입력 장치 | Chrome을 사용한다. 모니터 1대, 컴퓨터 웹캠을 준비한다. 외장 키보드·마우스는 유선으로 사용하며 블루투스는 사용할 수 없다. 노트북 내장 키보드는 사용할 수 있다. |
| 공간·전원 | 혼자 있는 폐쇄된 공간, 얼굴이 보이는 조명, 정리된 책상을 준비한다. 노트북 전원 어댑터와 휴대폰 충전선을 연결한다. |
| 휴대폰 | 안정적인 Wi-Fi와 거치대를 준비한다. iOS Proctor는 최신판으로 업데이트하고 Android는 안내된 경로의 재설치를 권장한다. 이 안내를 Codex 업데이트 허용으로 해석하지 않는다. |
| 신분증 | 실물 주민등록증·운전면허증·여권 중 하나를 준비한다. 모바일 신분증은 사용할 수 없다. 종류별 가림 범위를 공식 Proctor 안내에서 확인하고 사진·이름 등 확인 항목은 보이게 한다. |
| 감독 연결 | 컴퓨터 웹캠·전체 화면 공유·Cofa Proctor 연결을 유지한다. 설치용 QR과 응시 연결용 QR을 구별한다. |
| 네트워크 | 실제 장소에서 컴퓨터와 촬영용 휴대폰을 함께 연결해 안정성을 점검한다. 다운로드·업로드 각각 5Mbps 이상은 권장 사항이다. |

과제 시작 버튼을 누르면 녹화와 작업 타이머가 시작된다. 녹화 시작 후 휴대폰을 거치하고, 손·키보드·얼굴·모니터가 함께 보이게 조정한 뒤 신분증·안경 확인 절차를 따른다.

## 사전 체험과 환경 확인

사전 체험은 안내를 받은 뒤 본 과제 시작 전까지 1회, 15분이다. 연습용 문제와 작업은 평가에 반영되지 않는다. 체험을 반복할 수 있다고 가정하지 않는다.

| 확인 대상 | 체험에서 볼 내용 |
|---|---|
| 파일 | 과제 안내 열기, 파일 작성·저장, 저장 표시 |
| Codex | 실제 응답·권한·오류, 승인 대기·실행 중·완료 구별 |
| 실행 환경 | 필요한 명령·도구가 실제로 동작하는지 확인 |
| Browser | 서버 실행, 실제 포트·경로, 화면과 핵심 기능 |
| 지원·감독 | Cofa Helper, 필요한 MCP 설정, 웹캠·화면 공유·Proctor 연결 |
| 종료 흐름 | 체험 종료와 예시 후속 서술형의 진행 |

가이드의 `node --version`은 점검 명령의 예시이다. 특정 Node 버전·잠금 파일·helper 실행 지원을 보장하지 않는다. 실제 Skill·AGENTS 인식 경로, 파일 지속성, Codex 내부 독립 평가자 지원도 별도 확인 대상이다.

## 질문과 장애의 담당

| 상황 | 조치 |
|---|---|
| 화면 사용법·제출 절차가 궁금함 | Cofa Helper를 이용한다. 사전 체험에서도 확인할 수 있다. |
| 과제의 업무 맥락이 궁금함 | 실무자 에이전트에 문의한다. 목표·필수조건·제출물은 실제 README와 과제 안내를 기준으로 한다. |
| 접속 장애·반복 오류·감독 연결 문제 | 시험 환경의 문의·문제 신고 버튼으로 발생 시각·증상을 접수한다. 가능하면 단계·직전 동작·오류 문구도 기록한다. |
| 후속 서술형 오류 | 발생 단계·문항 번호를 함께 기록한다. 신고 기능 접근이 어려우면 발생 내용을 남긴다. |
| 연결 경고가 나타남 | 화면 안내에 따라 복구한다. 경고 자체를 부정행위 확정으로 해석하지 않는다. |

키·토큰·비밀번호는 신고 내용에 넣지 않는다. 문의·신고·재접속으로 타이머가 자동 정지하거나 연장되지는 않는다. 플랫폼 실무자 에이전트가 존재한다는 사실을 Codex 내부 R6 평가자 지원의 증거로 삼지 않는다.

## Browser에서 서비스 확인

사용자가 제공 플랫폼의 Browser에서 직접 화면과 핵심 동작을 확인한다. AI의 Computer Use 자동 조작은 사용하지 않는다.

| 상황 | 조치 |
|---|---|
| 서버를 시작함 | 터미널에 표시된 실제 포트를 확인하고 `0.0.0.0` 바인딩을 사용한다. |
| Browser에 연결함 | PORT에 실제 포트, URL 영역에 확인할 경로를 넣고 다시 연결한다. `3000`과 `/`는 예시이며 고정 요구가 아니다. |
| 화면이 열리지 않음 | 터미널 오류·서버 종료 여부 → 실제 포트 → 바인딩 → 경로를 확인한다. |
| 화면이 열림 | 버튼·입력·이동 등 핵심 기능을 직접 확인한다. |
| 확인 중 서버 터미널을 닫으려 함 | 해당 서버가 종료될 수 있으므로 서비스 확인 중 실행 터미널을 유지한다. |

터널이나 접속 주소를 임의로 구성하거나 외부 브라우저의 직접 접근 제한을 우회하지 않는다.

## 파일 저장과 충돌

필수 파일명·경로·내용은 실제 과제 안내를 따른다. 사용법 가이드의 README나 예제 서비스를 답안으로 만들지 않는다.

| 표시·상황 | 조치 |
|---|---|
| 저장 중 | 작업을 마친 뒤 저장됨 표시를 확인한다. |
| 저장되지 않은 변경·저장 실패 | 오류·연결을 확인하고 다시 저장한다. |
| 외부 변경 감지·디스크에서 삭제됨 | 에디터와 AI·터미널이 바꾼 작업 공간 파일을 비교한다. |
| 외부 변경 불러오기 | 작업 공간 파일의 내용을 에디터로 가져오는 선택이다. |
| 현재 내용으로 저장 | 에디터 내용을 작업 공간 파일에 저장하는 선택이다. |
| 파일 목록 갱신이 늦음 | 탐색기를 새로고침하고 실제 파일과 저장 상태를 확인한다. |

저장 충돌은 양쪽 내용을 확인한 뒤 해결한다. 필요한 수정이 사라지지 않았는지 확인하고 저장됨 상태를 다시 본다. 계획한 전체 페이지 새로고침 전에도 저장 상태를 확인한다.

## 시간·제출·종료

| 단계 | 시간과 변경 범위 |
|---|---|
| 전체 응시 | 10:00~14:00이며 늦게 입장해도 14:00 종료는 연장되지 않는다. |
| 과제풀이 | 과제 시작부터 최대 180분이다. AI 응답·실행, 검증·문서 작성·제출을 포함해 배분한다. |
| 제출 미리보기 | 열어도 작업 시간은 흐른다. 닫으면 확정 전 수정할 수 있다. |
| 제출물 확정 | 파일이 고정되며 이후 수정할 수 없다. 이것만으로 최종 제출 완료는 아니다. |
| 후속 서술형 준비 | 약 5분 대기가 안내되어 있다. 화면에 지연·재시도 안내가 표시될 수 있으며 전체 14:00 종료 안에 포함된다. |
| 후속 서술형 | 총 30분, 6문항, 문항당 5분이다. 첫 문항은 시작 조작 때, 다음 문항은 직전 답안을 제출하는 순간부터 시간이 계산된다. |
| 시간 종료 | 각 풀이 제한과 14:00 중 먼저 도달한 시점까지 입력한 내용만 반영된다. |

작업 종료 10분 전 제출 시작은 권장 사항이다. 이를 별도의 강제 마감이나 임의의 추가 여유 시간으로 바꾸지 않는다. 최소 응시 시간은 별도로 정해져 있지 않다.

제출 전 필수 파일 경로·저장 상태를 확인하고 미리보기를 연다. 미리보기에는 일부 파일만 표시될 수 있으므로 목록을 실제 제출 파일 전체로 간주하지 않는다. 확정 전 필요한 수정을 마친다.

후속 서술형에서는 AI와 복사·붙여넣기 없이 직접 답변한다. 확정 답안 수정이나 이전 문항 이동은 할 수 없다. 마지막 답변 뒤 처리·녹화 업로드를 기다리고 최종 완료 화면의 제출 ID·시각·파일 수·크기를 확인한다. 후속 서술형까지 끝나고 종료 안내가 표시되면 Proctor 녹화가 자동 종료되며 14:00까지 기다리지 않고 퇴장할 수 있다.

재접속하면 서버에 저장된 작업을 기준으로 이어가며 카메라·전체 화면 공유를 다시 연결한다. 저장 전 수정의 보존은 보장되지 않고, 재접속·비활성·일시정지 안내 중에도 응시 시간은 흐른다.
