# R5 — Work

**승인된 실행 단위를 수행하며 목표에 필요한 전문 작업을 찾고 실제 결과로 방법을 보정한다.** R4의 구조·현재 위치·판단 경계를 유지하되, 계획에 미리 열거한 방법으로 수행을 한정하지 않는다.

## 실행 기준

비단순 작업을 시작·재개할 때 해당 세션의 전체 `SESSION.md`에 담긴 R1~R4와 현재 요청·유효한 승인을 대조한다. 현재 버전 전체가 실제 입력에 있으면 중복 조회하지 않는다. 보존·갱신·분기 인계에는 R4의 [실행 맥락 연결](../my-r4-work-tree/references/execution-context.md)을 따른다. R4에 정한 1차 결과와 후속 의미 있는 결과에 도달하면 실제 산출물·평가 근거를 확인하고 SESSION의 R4 구획 전체에서 완료·현재 위치·남은 흐름을 갱신하고 다른 단계 원문을 보존한다. Hook이 재입력한 구획 전체와 기존 기준·다음 행동·멈춤 지점을 대조한다. R1~R3 변경은 하위 계약·계획의 유효성에 연결하고 필요한 재정렬을 현재 상태에 표시한다. Hook이 없거나 전달이 불완전하면 전체 문서를 직접 읽어 공백을 보완하고 재입력 성공으로 기록하지 않는다. 매 도구 호출의 작은 진척은 갱신·재입력 계기로 삼지 않는다.

작업 분리만으로 별도 채팅 생성·분기·메시지가 허용되지는 않는다. 명시적으로 요청받은 분기는 맡은 범위·결과·근거·남은 문제를 전달하고 메인이 통합한다. 분기 완료나 개별 R6 통과를 새 실행 권한으로 해석하지 않는다.

R4의 다음 실행 단위가 정해져 있고 현재 요청·사전 승인에 해당 실행 권한이 포함되어 있다면, 사용자의 `진행`을 그 단위의 시작 신호로 해석한다. 새 범위나 권한을 부여한 것으로 해석하지 않으며, 다음 단위나 필요한 권한이 불명확하면 정확히 부족한 것만 확인한다. 이번 단위의 현재 조건과 권한을 확인한 뒤 다음 사용자 판단 지점까지 수행한다. R4 실행 계획의 승인에는 그 범위 수행에 필요한 서브에이전트 등 내부 위임도 포함되므로 위임 자체의 반복 승인은 요구하지 않는다. 계획 제시만으로 실행하거나 위임하지 않는다. 위임 범위·산출물·완료 기준과 원래 범위·제한을 전달하고 결과를 메인 작업에서 검토·통합한다. 서로 선행하지 않는 독립 작업만 병렬 수행하며, 동일 파일·공유 상태의 동시 수정 충돌이나 의존성이 있으면 순차 처리한다. 위임했다면 모델·추론 강도를 덮어쓰는 설정이 없는지 확인한다. 실제 실행 설정을 확인할 수 있고 상속과 다르다면 그 결과를 승인된 설정의 수행으로 간주하지 않는다. 적합한 전문 Skill이 있으면 사용하되 모든 작업에 새 실행 기능을 요구하지 않는다. 실제 관찰과 기대 결과를 비교하고 R3 완료 기준을 확인할 최소 증거를 남긴다. R2 목표·R3 계약·R4 구조를 별도 원장으로 중복 기록하지 않는다.

## 수행과 보정

실행 중 필요한 전문 작업·원자료·도구와 현재 방법의 한계를 살펴 보정한다. 새 관찰에 따라 중요한 가정의 지지·반대 근거와 의존 작업에 미치는 영향을 갱신한다. 새 패턴은 검증할 가설로 두고 과업에 맞는 별도 근거로 확인한다. 중요한 차이가 없으면 승인 구간을 계속하고, 예상 밖 결과는 같은 가정의 실패 반복 대신 가정·방법을 구별할 확인으로 연결한다. 실행자의 점검·재검사는 R5 자체 점검이며, R6 완료 판정으로 기록하지 않는다.

여러 접근을 시도했는데도 목표한 효과가 나타나지 않으면 현재 접근의 핵심 가정과 한계를 재검토한다. 다음 시도가 앞선 시도와 무엇이 다르고, 어떤 개선·원인 구별·새로운 증거를 기대할 수 있는지로 재시도 가치를 판단한다. 이를 설명하지 못하면 같은 가정에 의존하는 추가 실행을 보류하고 사용자에게 방향 판단을 요청한다. 원인을 모르는 가정에 의존하는 후속 작업도 멈추되, 영향받지 않는 승인된 독립 작업은 계속할 수 있다.

같은 산출물·기준을 더 적은 비용으로 달성하고 범위·품질·위험·권한·복구 조건이 바뀌지 않는 방법은 AI가 보정한다. 추가 자원의 가치가 불분명하거나 결과·기준이 달라지면 현재 관찰과 대안을 사용자에게 제시한다. 근거 없는 수치 한도와 불필요한 테스트·로그는 만들지 않는다. 사용 중 확인하기로 한 항목을 임의의 사전 시험 의무로 바꾸지 않는다.

해결하려는 문제의 가치는 유효하지만 접근을 바꿀 근거가 있으면 피벗을 제안한다. 시도한 대안과 확보한 근거를 검토해도 개선 가능성을 설명하기 어렵거나, 사용자·팀이 지속을 감당하기 어렵다고 확인하면 보류·중단을 제안한다. 지속 의지·확신의 저하나 지속 가능성에 대한 의심이 제기되면 그 이유를 확인하며, 원인을 추정해 확정하지 않는다.

## 보고와 인계

**출력 순서 — 사용자 선택:** 의미 있는 결과나 사용자 판단 지점에서는 **결과 → 판단 근거 → 남은 판단·다음 행동** 순서로 알린다. 관찰된 사실·원인 가설·미확인·계속할 부담을 구분한다. 핵심 가정·목표·범위·권한이 흔들리면 영향과 복귀할 단계를 설명하고, 공식 방향 변경·프로젝트 보류·중단은 사용자 확인 뒤 처리한다. 손상이 커질 때는 먼저 안전하게 멈춘다. 매 도구 호출마다 전체 계획이나 R6 판정을 반복하지 않는다.

의미 있는 실행 단위를 닫을 때 판정 범위와 증거를 해당 수행에 참여하지 않은 별도 평가자에게 넘겨 R6 판정을 받는다. R6 통과 뒤에도 이미 승인된 다음 작업은 반복 승인 없이 이어가고, 새로운 판단·권한이 필요한 행동만 확인한다. 위임 결과의 통합과 필요한 평가·재질문이 끝나면, 근거와 미결 사항을 보존하고 추가 역할이 없는 하위 에이전트를 닫는다.
