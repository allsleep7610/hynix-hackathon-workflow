# 선례조사

## 목적과 책임

활용 가능한 기존 제품·요소·구현·업무 방식을 최대한 활용하고, 새로 풀어야 할 차이에 작업을 집중한다. 사용자가 제시한 ‘위대한 제품은 0에서 시작한 제품이 아니라 99에서 100을 만든 제품이다’라는 방향을 실행에 연결하기 위해 작성했다. 이는 기존 기반을 중시하는 목적이며 고정 재사용 비율이나 모든 제품에 대한 사실 주장으로 적용하지 않는다.

현재 목표에 활용할 수 있는 선례를 찾아, 그 효용을 만드는 요소와 작동 조건을 실제 적용 가능한 수준까지 파악한다. 선례를 기반으로 현재 목적에 맞게 변형하고, 결과를 원본과 대조해 가져오려던 장점이 보존됐는지 확인할 기준을 마련한다. 조사 항목·깊이·대조 방법은 활용하려는 요소와 자료의 특성에 맞춰 정한다.

R3·my-design·직접 조사 요청이 사용하는 공통 규격을 이 스킬에 모은다. 자료를 인상이나 추상 원칙으로만 요약해 실제 활용할 정보를 잃는 것을 줄이기 위한 분리다. R3는 계약, my-design은 최종 설계·구현·결과 검증의 책임을 유지한다.

## 조사 질문과 범위

현재 대화와 제공 자료에서 니즈·원하는 경험·목표·제약을 읽고, 확인 결과가 어떤 해법 선택이나 적용 방식을 바꿀지 조사 질문으로 만든다. 공개 근거와 기존 맥락으로 먼저 구체화하고, 사용자 소유 선택이나 중요한 해석의 빈칸이 현재 판단을 바꿀 때 확인한다. 서비스별 선호를 모두 먼저 입력하도록 요구하지 않는다.

대상과 포함·제외 범위, 필요한 근거와 시간·비용·접근 한계를 질문에 맞춰 정한다. 방향 선택에 필요한 근거와 실제 적용에 필요한 근거를 구별하고, 틀리면 고비용 후속 작업을 무너뜨리는 가정은 먼저 확인할 수 있게 한다. 이미 충분한 근거는 재사용한다.

## 선례 탐색

현재 과업과 원하는 결과, 그 결과를 만드는 작동 방식에서 탐색어와 후보 포함·제외 기준을 만든다. 관련 제품명에서 출발할 수 있지만 다른 분야의 유사 목표와 다른 해결 방식도 살핀다. 발견한 근거에 따라 질문과 탐색 범위를 보정하고, 인지도·외형만으로 후보를 고르지 않는다.

사용자 조사 선호: 서비스 내부 팀의 설계·개발·실험 사례 글과 외부의 서비스 분석 글도 탐색한다. 사용자가 이들 자료에서 도움을 경험했으므로, 관찰만으로 드러나지 않는 설계 의도·작동 이유·대안·비판을 찾는 출처로 활용한다.

사용자의 서비스 경험이나 기존 조사 자료가 탐색에 도움이 될 때 [사용 서비스와 조사 후보](references/services.md)의 질문 색인에서 관련 항목을 고른 뒤 해당 근거·활용 해석·조건만 읽는다. 사용 사실·조사에서 확인한 장점·사용자가 확정한 선호를 구별하며, 장점을 개인 취향으로 추정하지 않는다. 현재 대화에 충분한 정보가 있으면 재조회하지 않는다. 관련 조사 후보가 이번 선택에 어떤 영향을 주는지 검토하며 근거의 최신성·세부가 부족하면 원본을 더 확인한다. 목록 밖의 더 적합한 선례와 재사용할 공개 기반도 찾는다.

구조가 비슷한 다른 분야를 탐색하거나 선례의 관계·조건을 추상화하는 전문 방법이 필요하면 `my-abstraction`을 활용한다. 추상화한 원리와 검색어를 조사에 사용하되, 실제 근거 확인과 활용 판단은 이 스킬이 맡는다.

## 근거 확인과 방법 선택

판단 질문을 확인할 수 있는 자료와 관찰 방법을 선택한다. 화면의 구성은 해당 화면에서, 사용 과정은 실제 흐름이나 확인 가능한 데모에서 살피며, 구현을 가져오는 선택에는 관련 공식 문서·공개 구현을 확인한다. 이는 방법 선택의 예시이며 모든 자료와 도구를 거치는 고정 절차가 아니다. 접근 가능한 근거가 질문에 답하지 못하면 다른 근거를 찾거나 미확인으로 남긴다.

내부·외부 분석 글은 작성자의 의도·해석과 글에 제시된 관찰·측정 근거를 구별해 활용한다. 판단에 영향을 주는 내용은 인용한 원자료와 대상 제품·시점·조건을 확인하며, 근거가 부족한 해석은 추가 조사할 가설로 남긴다.

선례의 어떤 요소가 어떤 조건에서 효용을 만드는지 관련 상세까지 확인한다. 홍보 주장·직접 관찰·측정·추정·AI 해석을 구별하고 원본의 해당 구획과 확인 시점·범위를 연결한다. 효과 주장은 비교·측정 조건으로 뒷받침되는 만큼만 사용하며, 정지 화면에서 보이지 않는 동작이나 비공개 구현을 확인한 것으로 쓰지 않는다.

채택 판단을 바꿀 수 있는 반대 근거·예외와 현재 환경의 차이를 살핀다. 플랫폼·사용 장면이 달라 같은 요소의 효용이 바뀌는지, 개선한 지표 대신 잃은 가치가 있는지 검토한다. 판단을 좌우하는 주장의 근거가 약하거나 충돌하면 현재 결정을 바꿀 빈칸을 좁혀 관련 원본·다른 관찰로 더 확인한다. 남은 해석은 가설로 구별하고 무엇을 확인하면 판단이 달라질지 설명한다.

## 활용 판단과 인계

근거에서 이번 작업에 옮길 기반을 확보하고 재사용·변형·조합·개선 또는 배제 이유를 현재 니즈와 조건에 연결한다. 바로 쓸 수 있는 기반과 참고해 옮길 사고·패턴을 구별한다. 범용화할 때도 선례의 고유 요소와 적용 조건을 보존한다. 적용 전제·이용 조건·도입·변형·유지 부담이 선택을 바꾸면 검토하고, 맞지 않는 기반은 필요한 신규 작업과 함께 설명한다.

인계에서는 원본의 해당 근거·재사용할 상세와 실제 적용할 기반, 필요한 변경과 이유, 남은 미확인, 결과에서 확인할 기준이 이어지게 한다. 다음 담당자가 원본을 다시 해석해야만 중요한 적용 방식을 정할 수 있다면 설명만으로 인계를 마치지 않는다. 관찰·원본 명세와 현재 작업의 설계 제안을 구별하며, 선택에 영향을 준 선례나 기준을 드러내되 형식과 항목 수는 요청에 맞춘다. 선례의 성공이나 사용자 선호만으로 이번 작업의 효과를 확정하지 않는다.

결과 대조는 가져오려는 장점과 현재 목적에서 기준을 정한다. 담당 작업은 같은 성질을 비교할 수 있는 조건과 방법으로 원본과 결과를 대조해 의도한 변형과 의도치 않은 손실을 구별하고, 확인하지 못한 부분을 밝힌다. 화면의 조사 깊이나 대조 방법을 구체화하는 데 예시가 필요할 때만 [화면 활용 경험과 대조 예시](references/screen-detail.md)를 읽는다. 이 사례를 모든 화면의 필수 관찰 목록이나 고정 대조 절차로 적용하지 않는다.

## 조사 깊이와 종료

후보 탐색은 선택에 필요한 범위로 하고, 실제 활용할 선례는 다음 담당자가 중요한 선택을 다시 추측하지 않아도 될 구체성까지 깊게 확인한다. 필요한 상세의 공백을 추상 원칙 몇 개로 대신하지 않는다. 관련 요소의 깊은 조사와 전체 제품·시장·코드의 광범위한 조사를 구별한다.

인계만으로 이번 활용을 따라가 보며 다시 추측해야 하는 부분을 찾는다. 장점 재현에 필요한 원본의 빈칸은 더 조사하고, 현재 목적에 맞춰 새로 정할 부분은 변경안·사용자 판단으로 명시한다. 현재 활용을 바꾸지 않는 미확인은 조사 범위를 늘리는 이유로 삼지 않는다. 자료가 많아도 중요한 원본의 빈칸이 남을 수 있으므로, 확인 수준과 구현 뒤 검증할 부분을 구별한다.

방향 선택과 실제 활용의 조사 완료를 구별한다. 이번 질문에 답하고 필요한 인계까지 확보했으며 추가 확인이 선택·활용·검증을 바꿀 가능성이 낮으면 정리한다. 자원·접근 한계로 끝낸 경우 충분한 근거를 확보한 것과 구별하고 남은 미확인·영향을 밝힌다. 활용을 막는 원본의 빈칸은 완료로 처리하지 않고 후속 확인으로, 사용자 소유의 새로운 선택은 사용자 판단으로 연결한다. 자료 수·후보 수·고정 단계로 완료를 대신하지 않는다.

## 라우팅과 실행 경계

R3는 선례 조사 계획·판단에서, my-design은 선례 조사·활용에서 이 규격으로 라우팅한다. 이미 충분한 근거가 있으면 재사용한다. 기존 계약이 있으면 목표·범위·권한·완료 기준을 따르고, 독립 조사에는 현재 요청 범위에서 적용하며 R1~R6 전체를 새로 요구하지 않는다.

계획 요청에는 필요한 조사와 활용·대조 기준을 정하며, 실제 조회·실험·대조는 현재 요청과 승인된 실행 단위를 따른다. 결과는 계약 또는 담당 작업으로 돌려준다. 합의한 목표·범위·중요 가정·완료 기준·권한을 바꿀 결론은 영향과 대안을 제안해 사용자 판단에 맡긴다. 조사 결과가 구현·저장·외부 행동 권한을 추가하지 않는다.

디자인 근거의 전문 해석과 화면 결과 검증은 my-design, 개인 사실은 my-profile, 사용자 명시 호출한 장기 원칙·과거 개인 자료는 my-soul·my-materials의 책임을 따른다. 일반 선례 조사만으로 Soul·Materials를 자동 조회하지 않는다. 고유 관점의 해석이 실제 필요할 때 my-judgment-lens를 활용한다. 전문 판단 기준과 도구 사용법을 이 스킬에 복제하지 않는다.
