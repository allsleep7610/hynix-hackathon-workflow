# 사용 서비스·사이트 — 선례조사 출발점

## 확인 범위와 선택 조회

목록 출처: 이 세션의 사용자 직접 입력(2026-10-10). 아래 17개 명칭은 그대로 보존한다. 이용 빈도·사용 목적·좋아하는 요소는 항목별 미확인이다. 조사 기준일은 2026-10-11이며, 공개 본문·공식 도움말·제작팀 사례·외부 분석을 읽어 만든 **활용 후보**다. 실제 계정의 화면·전체 흐름을 실행하거나 효과를 재측정한 결과가 아니다.

아래 색인에서 현재 질문과 관련된 항목을 고르고 해당 구획의 근거·활용 해석·조건만 읽는다. 더 필요하면 관련 원본과 목록 밖 선례로 확장한다. 모든 항목을 매번 읽거나 장점을 모든 결과에 첨언하지 않는다. 근거가 현재 선택에 어떤 영향을 줬는지를 설명한다. 앵커는 문서 위치이며 자동 부분 로딩 기능은 아니다.

GPT는 이번 조사에서 ChatGPT를 후보로, 스프레드시트는 Google Sheets를 예시로 살폈다. 사용자의 구체 제품을 확정한 것은 아니다. 실제 도입이나 기능 비교가 제품 차이에 달리면 대상을 확인한다. 노트북LM의 도움말은 조회 당시 Gemini Notebook 명칭으로 리다이렉트되어, 사용자 명칭과 조회 대상의 차이를 남긴다.

## 조사 결과와 활용 후보

각 항목의 ‘확인한 기반’은 출처의 설명·보고 범위다. ‘활용 해석’은 AI가 현재 작업에 옮길 수 있다고 판단한 후보이며 개인 선호가 아니다. 과거 사례의 화면·수치·정책을 현재 제품의 고정 상태로 사용하지 않는다. 실제 채택에는 필요한 부분의 최신성·세부·적용 조건을 확인한다. 이 카탈로그는 후보 탐색까지의 깊이이며 구현용 명세를 대신하지 않는다.

<a id="toss"></a>
### 토스

**확인한 기반:** 제작팀은 보험 조회의 인증 단계를 줄일 수 없는 상황에서, 조회 후 얻게 될 결과를 예시 화면으로 먼저 보여준 사례를 설명한다. 완료 비율 개선은 내부 보고이며 공개 글만으로 표본·실험 설계 전체를 검증할 수 없다. TDS 글은 실제 사용에서 발견한 긴 문구·선택 상태·스크롤·접근성 문제를 공통 컴포넌트에 반영한 과정을 보여준다.

**활용 해석:** 사용자의 행동 부담 앞에 얻을 가치를 구체적으로 보여주고, 반복 요소의 사용 조건과 예외를 이미 갖춘 기반에서 가져온다. 현재 사용자에게 의미 없는 혜택 설명이나 실제 결과로 오해되는 예시를 추가하면 목적을 잃는다. 화면을 가져올 경우 원본의 해당 상태와 표시 규칙을 추가로 확보한다.

근거: [Value first, Cost later — 제작팀 사례, 2023-03-16](https://toss.tech/article/value-first-cost-later), [TDS 컴포넌트 개선 — 제작팀 사례, 2024-03-05](https://toss.tech/article/toss-design-system).

<a id="toss-invest"></a>
### 토스증권

**확인한 기반:** PC 종목 상세의 패널은 위치·크기를 바꾸고 추가·삭제하며 레이아웃을 저장할 수 있다고 구현자가 설명한다. 요구에 맞는 라이브러리를 찾지 못해 직접 구현을 선택하고, 이진 트리로 분할 관계를 표현한 이유도 공개한다. 별도 리서치 회고는 모바일의 간결함을 PC에 옮겼지만 기대한 성과가 나오지 않아 PC의 분석·비교 가치를 재검토했다고 보고한다.

**활용 해석:** 많은 정보를 함께 판단하는 화면은 관련 정보의 동시 비교와 사용자 작업 상태 유지에서 배울 수 있다. ‘토스처럼 간결하게’만으로 충분한 요구가 되지 않는다. 같은 외형·기능이라도 플랫폼과 사용 목적이 다르면 효용이 바뀐다. 공개된 설명·코드는 참고 기반이며 전체 레이아웃 구현의 재사용 가능성을 확인한 것은 아니다.

근거: [그리드 레이아웃의 요구·대안·자료구조 — 제작팀 구현 사례](https://toss.tech/article/frontend-tree-structure), [토스증권 PC의 가치 재검토 — 리서처 회고, 2025-11-27](https://toss.tech/article/uxr-survival).

<a id="youtube"></a>
### 유튜브

**확인한 기반:** 2021년 제작팀 설명은 클릭·시청 시간 외 설문·좋아요·공유 등의 신호를 함께 사용하고, 오래 본 시간과 사용자가 가치 있다고 느끼는 시간을 구별한다. 2020년 외부 인터뷰 연구의 초록은 중년 이용자가 추천 시스템의 존재를 알아도 이해는 제한적이었다고 보고한다.

**활용 해석:** 추천과 탐색에서는 관찰한 행동과 실제 만족을 분리해 판단하고, 추천 이유와 조절 방법이 필요한지 검토한다. 당시 알고리즘 설명을 현재 구현으로 고정하거나 제한된 연구 대상을 전체 이용자에게 일반화하지 않는다. 이번 외부 연구는 초록 범위만 확인했으므로 세부 인터뷰 근거가 필요하면 본문을 읽는다.

근거: [추천 신호와 만족 — 제작팀 설명, 2021-09-15](https://blog.youtube/inside-youtube/on-youtubes-recommendation-system/), [추천에 대한 이용자 이해 — 외부 원저 연구 초록, 2020](https://arxiv.org/abs/2008.03202).

<a id="kakaomap"></a>
### 카카오맵

**확인한 기반:** 공식 글은 장소를 폴더로 묶어 지도에 표시·공유하고, 다른 사람의 폴더를 구독하면 이후 변경도 받아보며, 표시한 폴더 상태를 계정에 유지하는 구조를 설명한다. 공유는 공개 폴더에 한정된다.

**활용 해석:** 수집을 목적별 묶음으로 만들어 실제 위치 판단에 이어 붙이고, 개별 항목보다 묶음을 재사용할 수 있다. 공유한 복사본과 계속 갱신되는 구독은 서로 다른 선택이다. 공개 범위와 편집 주체를 유지해야 하며, 실제 적용에는 최신 제품의 폴더·표시·공유 조건을 확인한다. 오래된 안내의 개수 제한은 현재 기준으로 채택하지 않는다.

근거: [폴더별 즐겨찾기 — 공식 안내, 2018-04-12](https://kakaomap.tistory.com/171), [공유·구독·표시 상태 동기화 — 공식 안내, 2020-08-24](https://kakaomap.tistory.com/320).

<a id="instagram"></a>
### 인스타

**확인한 기반:** Meta는 Feed·Stories·Reels 등의 추천 설명을 시스템 카드로 제공하고, 추천 이유를 제품 안에서 확인하며 사용자가 선호·비선호 신호를 줄 수 있게 하는 접근을 설명한다. 행동·설문 등 여러 예측을 함께 쓰며 단일 신호가 가치의 완전한 척도는 아니라고 밝힌다.

**활용 해석:** 개인화된 결과에 이해할 수 있는 이유와 사용자가 바꿀 수 있는 선택을 연결한다. 회사가 공개한 설명은 의도와 기능의 근거이며, 사용자가 실제로 이해하거나 만족했다는 측정 근거는 아니다. 필요한 피드의 현재 조절 방식은 해당 화면에서 확인한다.

근거: [추천 설명·피드백·조절 — 운영사 설명, 2023-06-29](https://about.fb.com/news/2023/06/how-ai-ranks-content-on-facebook-and-instagram/).

<a id="gpt"></a>
### GPT

**확인한 기반:** 조사 후보인 ChatGPT의 Projects는 관련 대화·파일·프로젝트 지시를 한 작업 맥락에 모으고 반복 작업에 활용하는 기능이다. 도움말은 프로젝트 맥락과 접근 조건을 설명한다.

**활용 해석:** 반복 작업마다 같은 맥락을 다시 입력하는 부담을 줄이고, 어느 자료·지시가 결과를 이끄는지 연결할 수 있다. 자료를 모았다는 사실만으로 필요한 정보가 항상 정확히 회수되거나 답변 품질이 보장되지는 않는다. 실제 사용 제품·메모리·공유 범위와 현재 설정은 미확인이다.

근거: [Projects — 공식 도움말, 2026-10-11 조회](https://help.openai.com/en/articles/10169521-projects-in-chatgpt).

<a id="naver-webtoon"></a>
### 네이버웹툰

**확인한 기반:** MY 도움말은 관심·최근 본 작품과 새 이야기·미리보기·무료 충전 상태를 연결하고, 최근 본 작품 중 새 에피소드가 생긴 대상을 ‘지금 볼’ 목록으로 모으는 기능을 설명한다.

**활용 해석:** 저장한 콘텐츠를 다시 찾아야 하는 부담을 줄이려면 ‘내 관심 + 지난 이용 + 지금 이용 가능한 변화’를 이어 볼 수 있다. 저장 목록 자체와 지금 할 수 있는 행동을 구별한다. 실제 읽음 동기화·화면 흐름·정렬의 사용성은 추가 확인 대상이며, 새 콘텐츠 노출이 읽기 만족을 높였다는 측정은 확보하지 않았다.

근거: [MY 메뉴별 기능 — 공식 도움말, 2026-10-11 조회](https://help.naver.com/service/5635/contents/7929?lang=ko&osType=MOBILE).

<a id="naver-series"></a>
### 네이버시리즈

**확인한 기반:** 매일10시무료는 이벤트 작품에서 시작하면 즉시 이용권을 주고 다음 날부터 밤 10시에 지급한다고 안내한다. 이용권 유효기간은 24시간이고 시작·중단은 앱에서 가능하다고 명시한다.

**활용 해석:** 다음 이용 가능 시점과 혜택 조건을 명확히 보여줄 수 있는 선례다. 고정 시점에 돌아오게 하는 설계는 사용자의 일정에 맞을 때 의미가 있으며, 유효기간으로 압박을 만드는 효과까지 장점으로 채택하지 않는다. 작품·행사별 범위와 최신 조건을 확인하고 재방문 증가를 독서 만족으로 대체하지 않는다.

근거: [지급 시점·유효기간·앱 조건 — 공식 도움말, 2026-10-11 조회](https://help.naver.com/service/5629/contents/10053?lang=ko&osType=COMMONOS).

<a id="kakaopage"></a>
### 카카오페이지

**확인한 기반:** 개발사가 제공한 앱 설명은 시계 아이콘으로 기다리면 무료 작품을 표시하고, 무료 한 편을 본 시점부터 일정 시간이 지나면 새 이용권을 충전하는 구조를 설명한다. 무료·유료 회차 조건은 작품마다 달라질 수 있다고 고객센터가 답한다.

**활용 해석:** 네이버시리즈의 고정 시각 지급과 달리 개인의 이용 시점에 맞춰 다음 접근이 열리는 후보다. 회차별 이용 가능 상태와 기다림·유료 선택의 차이를 명확히 전달하는 데 참고할 수 있다. 학습·업무의 필수 행동을 인위적으로 막는 방식으로 그대로 옮길 근거는 없다. 실제 앱의 충전·결제 흐름과 만족·성과는 확인하지 않았다.

근거: [기다리면 무료 — 개발사 앱 설명과 고객센터 답변, 2026-10-11 조회](https://play.google.com/store/apps/details?hl=ko&id=com.kakao.page). 회사 보도자료는 본문 접근이 제한되어 핵심 근거로 사용하지 않았다.

<a id="threads"></a>
### 스레드

**확인한 기반:** 공식 안내는 관심 프로필·주제의 사용자 피드를 만들고 공개·공유하며, 다른 공개 피드를 탐색해 고정하는 기능을 설명한다.

**활용 해석:** 관심을 개별 항목으로만 저장하는 대신 다른 사람이 다시 사용할 수 있는 탐색 묶음으로 만들 수 있다. 누구의 어떤 기준으로 구성됐는지와 공개 범위가 필요하다. 공유 가능하다는 사실로 그 피드의 품질이나 사용자 만족을 확정하지 않는다.

근거: [사용자 피드 구성·공개·공유·고정 — 공식 안내, 2025-02-04](https://about.fb.com/news/2025/02/share-custom-feeds-on-threads/).

### 노트북LM

**확인한 기반:** 조회한 도움말은 답변에 쓸 자료를 선택하고, 인용에 마우스를 올려 문구를 보거나 선택해 원래 위치와 맥락으로 이동하는 기능을 설명한다. 조회 대상은 Gemini Notebook 도움말로 리다이렉트됐다.

**활용 해석:** AI 설명에서 근거로 돌아가는 부담을 줄이고, 이번 판단의 자료 범위를 사용자가 이해·조절하게 하는 선례다. 출처 연결은 검토를 돕지만 원자료의 정확성·충분성이나 답변의 충실성을 보장하지 않는다. 외부 자료 탐색과 선택한 자료 안의 답변은 구별한다.

근거: [자료 선택·인용 위치 확인 — 공식 도움말, 2026-10-11 조회](https://support.google.com/gemininotebook/answer/16179559?hl=en). 사용자 이용 제품과 현재 화면은 별도 미확인이다.

<a id="spreadsheet"></a>
### 스프레드시트

**확인한 기반:** 제품을 특정하지 않은 사용자 명칭을 보존하고 Google Sheets를 예시로 조사했다. 공식 문서는 셀의 수식으로 계산을 자동화하고 관련 셀을 색으로 표시하며, 함수 설명·예시와 제안을 제공하고 사용자가 제안을 수락·거절할 수 있다고 안내한다. 공동 작업 문서는 댓글·버전 이력·필터 보기 등을 설명한다.

**활용 해석:** 입력과 결과의 관계를 드러내고 필요한 부분을 직접 수정하며 다시 계산하는 구조를 참고할 수 있다. 계산이 실행되는 것과 계산이 맞는 것은 구별한다. 특정 제품의 협업·복구 기능을 모든 스프레드시트에 일반화하지 않는다. 실제 제품·데이터·수식 오류·공유 권한은 적용 시 확인한다.

근거: [수식·참조 표시·제안 — 공식 도움말](https://support.google.com/docs/answer/46977?hl=en), [협업·이력·필터 보기 — 공식 도움말](https://support.google.com/docs/answer/9331169?hl=en). 후자는 최초 조회에서 본문 일부를 확보했으나 재조회가 제한돼 상세 복구 절차는 이번 근거 범위에 넣지 않았다.

**확인한 기반:** 제작팀은 높은 일일 목표 때문에 매일 참여해도 streak가 끊기는 문제를 보고, 한 수업으로 연속 참여를 유지하고 일일 목표 진척은 따로 보여주도록 바꿨다고 설명한다. 내부 A/B 결과는 유지 지표 개선과 일일 목표 달성 감소를 함께 보고한다. 외부 디자이너는 streak의 압박과 휴식·복구 방향을 검토하지만 개선 효과를 미검증 가설로 표시한다.

**활용 해석:** 돌아오게 하는 최소 참여와 실제 성취를 구별하고, 동기 장치가 실패 부담을 키우는지도 본다. 초기 습관 설계에 참고할 수 있으나 streak·접속 유지가 학습 성과의 증거는 아니다. 외부 분석의 제품 묘사와 제안 수치를 현재 사실·검증 결과로 채택하지 않는다.

## 이 참조의 갱신 경계

이번 내용은 2026-10-11 사용자가 초안을 확정하고 로컬 적용·GitHub 병합을 요청한 조사 후보 참조다. 사용자가 특정 요소와 이유를 확인하면 관련 항목 가까이에 발언 출처·범위·조건을 연결하고 조사 해석과 구별한다. 개인 사실·장기 원칙에 정본이 있으면 그 출처를 연결해 별도 중복 관리하지 않는다. 이후 조사 결과의 장기 저장·채택은 당시 요청 범위와 자산 소유 책임을 따른다.

다음 과업은 이 후보의 이름을 다시 나열하는 데서 끝내지 않는다. 관련 근거가 충분하고 현재에도 적용되는지 먼저 판단하고, 실제로 가져올 부분의 원본·상태·조건·동작·구현을 필요한 만큼 확보한다. 다른 자료가 더 적합하면 후보를 바꾸고, 참조의 모든 장점을 필수 기준으로 만들지 않는다.
