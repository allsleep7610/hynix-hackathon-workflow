# 시험 작업공간의 상태 전달 연결

하네스를 GitHub에서 반입·적용하거나 Hook 등록·실패·SESSION 경로를 다룰 때 읽는다. 이 문서는 상태 전달 방법이며 R1~R6 출력 형식이나 실행 권한을 바꾸지 않는다.

## 기본 경로 — 직접 조회와 저장

제공 환경의 파일 조회·편집 도구로 해당 세션의 SESSION을 사용한다. Node나 Hook의 설치·성공을 선행 조건으로 두지 않는다. 시작·재개·맥락 압축 후 및 원문 누락·충돌 때 최신 전체 원문을 확인한다. 중요한 승인·조건 변경과 의미 있는 실행 결과를 저장한 뒤 현재 요청·유효한 승인·다음 행동과 대조한다. 완전한 최신 문맥이 있으면 중복 읽지 않는다.

Hook이 이미 알려준 정본이나 이번 세션에서 명시적으로 정한 위치가 있으면 그대로 사용한다. 새 세션에 정본이 없을 때만 작업공간 안에 다른 세션과 구별되는 전용 위치를 정하고 `templates/SESSION.md`를 새 파일로 복사한다. 기존 파일을 덮어쓰지 않는다. 정본의 정확한 위치를 현재 세션 맥락에 남기고 재개·압축 인계에도 전달한다. 위치가 누락되면 확인 가능한 대화·인계에서 찾고, 식별할 수 없으면 위치만 확인한다. 최근 수정 파일·다른 세션·옛 R4를 자동 상속하지 않는다.

저장은 [SESSION 규격](session-document.md)의 잠금·버전 대조·원문 보존을 따른다. Node가 없으면 제공된 파일 도구·셸 중 이 규약을 지킬 수 있는 방법을 사용한다. 원문을 읽고 기록한 사실은 자동 Hook 전달 성공이나 사용자 승인·R6 통과의 증거가 아니다.

## 선택 경로 — 기존 실행기로 Hook 연결

기존 하네스 반입 과정에서 패키지를 허용된 과제 작업공간 안에 배치하고 원래 Skill 발견·AGENTS 인식 방법을 유지한다. 초기 설치 흐름을 전면 개편하지 않는다. Node가 이미 있고 허용된 Hook 기능이 있을 때만 아래 등록 도구를 사용한다. Node가 없거나 Hook 지원이 없으면 기본 경로로 계속하며 설치·Codex 업데이트·외부 AI로 보충하지 않는다.

1. 현재 작업공간과 패키지 위치, 기존 정본과 세션 식별자, 기존 Hook 설정을 확인한다. 패키지는 작업공간 자체 또는 그 안의 폴더에 둘 수 있다.
2. `<패키지>/.hynix-harness/hooks/setup.mjs --workspace <작업공간 절대경로> --check`를 제공 환경의 기존 Node로 실행해 충돌을 먼저 확인한다. 사용자·프로젝트의 기존 세션 훅이나 inline Hook 충돌을 자동 대체하지 않는다.
3. 기존 정본이 없으면 같은 명령에서 `--check`를 빼고 세 이벤트의 연결을 등록한다. 기존 정본이 있으면 확인한 실제 세션 ID와 `--session-id <ID> --document <정본 경로>`를 함께 지정한다. 실제 ID를 모르면 기본 경로를 유지하고 정본을 새로 만들지 않는다. `--document`의 상대경로는 작업공간 기준이다.
4. 도구는 프로젝트 `.codex/hooks.json`만 병합하고 기존 내용을 runtime 아래 백업한다. 세 이벤트는 SessionStart·UserPromptSubmit·PostToolUse다. 같은 도구 재실행은 자체 등록을 중복 생성하지 않는다. 사용자 전역 설정·인증·모델은 변경하지 않는다.
5. 반환 모드 `hooks-configured-unverified`는 파일 등록 결과다. 제공 Codex가 요구하는 정상 신뢰 확인은 사용자에게 이유·대상·조작을 안내하고, 신뢰 상태를 자동으로 수정하거나 우회하지 않는다. 현재 세션의 설정 재읽기/재개 필요 여부와 실제 이벤트 결과를 확인하기 전에는 작동 성공으로 기록하지 않는다.

새 Hook 세션의 기본 정본은 `<작업공간>/.hynix-harness/runtime/sessions/<실제 세션 ID>/SESSION.md`다. 처음 생성된 빈 규격은 과거 합의가 아니며, 해당 세션에서 확인한 확정 원문만 복원한다. 기존 정본을 명시적으로 바인딩하면 `<작업공간>/.hynix-harness/runtime/bindings/<ID>.json`이 그 원문 위치를 가리킨다. 원문을 복제·이동하지 않는다.

현재 설정과 문서가 변하면 새 기준의 Hook 신뢰 확인이 필요할 수 있다. 공식 지원 참고: [OpenAI Hooks](https://learn.chatgpt.com/docs/hooks). 이 문서가 시험 제공 환경의 지원·반입 승인을 증명하지는 않는다.

## 실패·전환·제거

등록 거부·미신뢰·실행 실패·누락·잘린 전달이 있으면 확인된 같은 정본 전체를 직접 읽고 필요한 실행의 공백을 보완한다. 실패한 Hook의 자동 주입을 성공으로 표시하지 않는다. 정본을 못 읽거나 승인 원문이 불명확하면 영향받는 실행만 멈추고 부족한 위치·원문·권한을 확인한다. 관련 없는 승인 작업은 계속할 수 있다. 이벤트별 자동 실행과 중복 억제는 스킬만으로 보장되지 않는 기능 차이다.

등록 해제는 같은 Node로 `setup.mjs --workspace <작업공간> --remove`를 실행한다. 소유한 명령만 제거하고 다른 Hook 및 SESSION은 보존한다. Node가 없으면 현재 설정과 `.hynix-harness/runtime/registration.json`의 소유 명령을 대조해 제공 파일 도구로 그 항목만 제거한다. 기존 백업 전체를 덮어써 다른 후속 변경까지 되돌리지 않는다. 강제 삭제로 신뢰·관리 정책을 변경하지 않는다.

공개 반입 파일은 코드·스킬·템플릿·합성 테스트뿐이다. `.hynix-harness/runtime/`의 실제 SESSION·캐시·백업·등록 기록과 생성된 `.codex/hooks.json`은 공개하지 않는다. 시험 작업·결과를 저장소에 Push하지 않는다.
