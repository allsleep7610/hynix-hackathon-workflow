# 스킬 제작 배경 기록

개인 Skill을 새로 만들 때 `references/design-context.md`를 작성한다. 실행 지침을 길게 만들지 않고 만든 이유와 개념을 사이트에서 다시 읽기 위한 사용자 선택이다. 기존 스킬을 일괄 소급 작성하거나 라벨링하지 않는다. 기존 스킬은 시각화를 다듬은 뒤 사용자가 하나씩 라벨링한다.

## 작성

`scripts/init-design-context.mjs <개발 스킬 폴더> [분야]`로 빈 초안을 만들 수 있다. 기존 문서를 덮어쓰지 않는다. 생성한 초안의 네 구획에 현재 제작 대화·확인된 근거로 내용을 기록한다. 참고 기반은 작동 시 읽는 입력 목록이 아니라 이 스킬을 만들 때 참고한 개념·방법·발상이다. 모르면 `미확인`이라고 남기며 외부 이론과의 이름 유사성만으로 채우지 않는다.

```markdown
---
format: skill-design-context-v1
skill: my-example
status: draft
skill_source_sha256: 여기에_SKILL.md의_SHA256
viewer_group: learning
---
# 제작 배경

## 만든 니즈
누구의 어떤 불편과 원하는 변화를 위해 만들었는지 기록한다.

## 참고 기반
만들 때 사용한 개념·방법과 출처, 확인된 배경과 미확인을 구별한다.

## 작동 방식
입력에서 판단·행동·결과로 이어지는 핵심 관계와 조건을 적는다.

## 주의점
적용 범위·오해하기 쉬운 경계·성립하지 않는 조건을 적는다.
```

`skill_source_sha256`는 개발 원본 `SKILL.md`의 바이트 기준 SHA-256이다. 초안 생성기가 현재 값을 넣는다. `viewer_group`은 선택값이며 workflow / judgment / maintenance / design / learning / life 중 하나다. 모르면 생략한다. 정해지지 않은 분야 때문에 스킬 등록을 막지 않는다.

## 확인과 갱신

생성 직후는 `draft`다. 네 항목이 작성되어도 확인 전에는 확정 라벨로 표시하지 않는다. 사용자가 해당 내용을 확인하면 `confirmed`로 바꾼다. 사용자가 이미 정확한 내용을 확정했다면 같은 판단을 다시 묻지 않는다. `미확인`도 사용자가 그렇게 확인한 상태로 명시할 수 있다.

`SKILL.md`를 수정하면 관련 설명이 여전히 맞는지 함께 검토하고 원문 해시를 갱신한다. 확인되지 않은 변경은 `draft`로 두며 해시만 자동으로 바꿔 확인을 대신하지 않는다. 초안 생성기는 갱신 도구가 아니다. 기존 문서의 수정을 보존하며 필요한 내용과 해시를 직접 갱신한다.

본문에는 이 문서가 실행 지침이 아닌 제작 배경임을 드러내고 필요한 때 읽는 링크만 둔다. 기록이 없거나 오래됐어도 `SKILL.md`의 조회·사용을 막지 않는다. 설치와 GitHub 반영은 승인된 대상·범위에서 수행하며, 개발 원본과 설치본·GitHub를 구별한다.
