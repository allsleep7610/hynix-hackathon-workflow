# AI 행동 지시 작성·수정

## 목적과 책임

사용자가 전체 사용·행동 흐름을 이해하고 판단하는 범위에서 모델 능력을 최대한 활용하도록 지침을 정돈한다. 행동과 작성 이유를 함께 남겨, 이후 수정에서도 유지할 목적과 변경 이유를 파악할 수 있게 한다.

명시된 AI 행동 지시·사용자 관리 Skill·AGENTS·워크플로우 지침에 적용한다. 실제 Skill 제작·수정은 바닐라 공식 `skill-creator`와 함께 수행하며, 이 Skill은 사용자 고유의 작성·수정 기준을 보완한다.

## 공통 작성 기준

먼저 사용자 입력·원하는 변화·기존 작성 의도를 읽고, 필요한 판단·행동과 그 이유를 연결한다. 확인된 의도와 AI 해석을 구별하고 미확인 과거 이유를 만들지 않는다. 수정할 때는 지침과 현재 의도 설명을 함께 갱신한다.

모델의 탐색·추론 여지를 유지하며 일반 설명·중복을 줄인다. 실제 권한·범위와 명령·스키마·모델 바인딩·복구·차단 등 기계적 조건의 의미는 보존한다. 간결화로 권한을 넓히거나 기술적 제어를 설명문으로 대신하지 않는다. 충돌은 영향받는 행동 전에 드러낸다.

## 표현 기준 — 사용자 취향

표현·출력 형식은 확인된 사용자 선택과 적용 범위에 맞춘다. 일회성 요청을 보편 규칙으로 만들지 않는다.

## Skill·워크플로우 작성 또는 수정 시

[작성·수정 기준](references/authoring.md)을 읽어 의도·라벨·파일 구조·품질을 확인한다. 일반 지시문 정돈에서는 읽지 않되, 그 내용을 변경하는 요청에는 해당 기준을 적용한다. 중요한 작성 이유는 해당 Skill 본문에 짧게 유지하고, 조건별 상세만 참조로 분리한다.

사용자 선택: 새 개인 Skill을 제작·저장할 때 AI는 **만든 니즈·참고 기반·작동 방식·주의점**의 실제 설명을 해당 스킬의 `references/design-context.md`에 함께 작성한다. 제작 대화와 확인한 근거를 사용하고, 참고 기반은 제작에 사용한 개념·방법을 적으며 모르는 부분은 미확인으로 남긴다. 제작 완료 전에 네 항목의 내용과 원문 대응을 확인한다. 빈 양식이나 초안 파일 생성만으로 이 작성을 완료 처리하지 않는다. 문서 형식·확인 상태는 작성·수정 기준을 따르며, 기존 스킬의 소급 라벨링은 사용자에게 남긴다.

## 출력과 실행

직접 변환 요청에는 명시된 대상의 재사용 가능한 지시문 하나만 반환한다. 요청된 의도·라벨은 지시문 안에 포함하고 별도 비평·변경 로그는 붙이지 않는다. 변환한 지시를 실행하거나 기존 파일을 수정하지 않는다.

승인된 구현의 작성 기준으로 사용하면 원래 작업의 범위·권한·검증 절차를 따른다. 직접 변환의 파일 수정 금지를 구현 작업 전체에 적용하지 않는다.
