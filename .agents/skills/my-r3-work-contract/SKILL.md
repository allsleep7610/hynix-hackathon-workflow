# R3 — 작업 계약

**R2의 목표를 작업 위치·산출물·범위·완료 기준·핵심 가정·권한이 분명한 실행 가능한 계약으로 만든다.** 현재 조건과 정본을 확인하고, 기존 해법에서 무엇을 배울지와 어떻게 조사할지를 계약에 연결한다. 활용할 기반과 새로 풀 차이를 구분해 목표 달성에 필요한 작업을 정한다. 사용자가 R3를 직접 요청하면 명시적인 계약 검토로 들어간다.

명확하고 짧고 되돌리기 쉬운 작업은 대상·변경 범위·완료 상태·권한만 정돈한다.

## 선례조사와 계약

사용자 니즈·원하는 경험·확인된 서비스 선호·유사 목표에서 활용할 기존 기반과 이번에 바꿀 판단을 정한다. 선호가 미확인이어도 관련 조사 후보와 공개 근거로 시작할 수 있으며, 사용 사실이나 조사한 장점을 개인 취향으로 확정하지 않는다. 기존 요소를 최대한 활용하고 새로 풀 차이에 작업을 집중하되, 현재 조건에 맞지 않거나 도입·변형·유지 부담이 큰 기반은 필요한 신규 작업과 함께 검토한다.

선례 조사 계획·판단은 `my-precedent-research`의 공통 규격을 따른다. R3에서는 조사 목적과 출발 질문, 결과를 사용할 결정, 범위·자원·접근 제약·권한과 사용자 판단 지점을 정한다. 해법이 열려 있으면 사용자 니즈와 원하는 경험에 부합하는 기존 해법을 탐색하되, 이미 확보한 근거와 현재 결정을 바꿀 불확실성에 따라 조사 출발점을 정한다. 조사 전에 특정 해법이나 후속 조사 항목·깊이·방법을 미리 고정하지 않는다.

세부 조사는 결과에 따라 필요한 질문이 달라지므로, R4에서 현재 실행할 묶음만 구체화하고 발견한 근거로 후속 조사를 보정한다. 현재 결정에 필요한 근거와 활용 가능성을 판정할 기준은 분명히 하되, 선행 결과에 달린 선택은 잠정으로 남긴다. 틀리면 작업을 무너뜨리는 가정은 고비용 의존 작업 전에 확인한다. 계약 대상·범위·현재 상태를 확인하는 사전 조회와 본조사를 구분하며, 조사 계획 자체를 실행 승인으로 해석하지 않는다.

조사 결과는 활용할 기반, 적용·변형 또는 배제 이유, 남은 신규 작업으로 연결해 계약의 가정·범위·완료 기준과 대조한다. 제품명·링크 나열이나 공통 규격의 복제로 이를 대신하지 않는다. 계약 안의 조사 보정은 기존 실행 권한에 따라 진행하고, 목표·범위·완료 기준·중요 가정·권한이 달라지는 경우에는 영향과 대안을 설명해 사용자 확인을 받는다.

기존 작업을 이어받으면 현재 작업 위치와 정본에서 계속한다. 새 작업의 위치와 기준 파일은 시험 플랫폼이 제공한 작업공간 안에서 정한다.

계약 문서에는 필요한 만큼 작업 위치와 기준 정본, 선례 관계·조사 계획과 미확인, 산출물과 포함·제외 범위, 완료 기준과 증거, 중요한 사실·핵심 가정·사용자 결정, 권한·보호·복구, 의미 있는 시간·비용·복잡성 제약을 담는다. 문서 양식은 고정하지 않는다. 다만 비단순 계약이나 명시적인 R3에서는 문서 작성으로 대화 설명을 대체하지 말고 **작업 위치 → 선례 → 산출물과 포함·제외 범위 → 완료 기준 → 핵심 가정 → 사용자 결정** 순서로 각각의 판단 이유를 함께 제시한다. 선례 항목에서는 기존에 확인한 기반, 앞으로 조사할 조건, 결과에 달린 잠정 선택을 구분해 설명한다. 해당하지 않거나 확인되지 않은 항목도 그 이유 또는 미확인을 밝힌다. 권한과 보호·복구 경계는 사용자 결정 항목에 연결해 설명한다.

계약을 통과시키기 전에 다음을 검토한다.

- 틀리면 전체 작업이 무너지는 가정에 지지 근거가 있는가. 새 정보가 기존 가정이나 해법 선택을 흔들면 계약을 고쳐야 하는가.
- 보안·개인정보·실행 권한·복구 경계와 빠진 요구·완료 조건이 있는가.
- 활용할 기존 해법을 검토할 계획과 신규 구현 여부를 판단할 기준이 있는가. 목표 기여에 비해 조사·도입·구현·유지 부담이 지나치게 커지지 않는가.

최초의 비단순 계약도 이 검토를 거쳐 위 항목을 사용자에게 설명하고 확인받는다. 단순하고 현재 요청만으로 충분한 계약은 짧게 정돈하고 별도 승인 질문 없이 통과할 수 있다.

현재 요청과 유효한 사전 승인을 대조하고, 부족하거나 불명확한 권한은 `my-action-authority` 기준으로 확인한다. 계약 합의를 새 실행 권한으로 해석하지 않는다. 다음 실행 단위를 막는 미확인을 적어 두기만 하고 통과시키지 않으며, 사용자 소유 선택이나 의미 있는 계약 변경은 이유와 영향을 설명해 확인받는다.

승인된 계약의 후속 작업은 다시 쓰지 않고 달라진 조건만 확인한다. 확정한 R3 계약 전체는 `my-session-save`의 SESSION R3 구획 한 곳에 원문 그대로 보존한다. 별도 계약 파일은 또 다른 현행 정본으로 관리하지 않는다. 검토된 계약은 R4가 작업·의존관계·다음 실행 단위로 나눈다.
