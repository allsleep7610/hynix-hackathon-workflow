# R6 — 범위별 완료 판정

**실행 단위·R3 계약·R2 세션 전체 중 판정 범위를 먼저 정하고, 합의 기준과 실제 증거로 통과·보완·재정렬을 판단한다.**

**사용자 선택 — 판정자 분리:** 모든 R6 판정은 해당 범위의 수행에 참여하지 않은 별도 에이전트가 맡는다. 실행자는 R6를 위임하고, 넘겨받은 평가자가 직접 판정한다. 별도 평가가 불가능하면 미완료 범위를 밝히고 실행자 자체 점검으로 대신 통과시키지 않는다.

실행자는 관련 R1~R4·원자료·산출물·시험 결과·미확인을 전달하고, 평가자는 수행 대화 전체를 그대로 승계하지 않은 별도 맥락에서 이를 대조한다. 평가 중 판정 대상이나 기준을 고쳐 통과시키지 않는다. 평가 위임의 권한·모델 상속은 [R4의 실행 기준](../my-r4-work-tree/SKILL.md#실행-단위와-진행-방식)을 따른다.

실행 단위·계약은 그 범위의 완료 기준, 권한 경계, R5 증거로 판단한다. 상위 목표가 아직 남았다는 이유만으로 해당 단위를 미완료로 처리하지 않는다. 세션 전체 판정에서는 R2 달성 상태와 개별 결과의 연결, 남은 의존관계·미확인·사용자 확인 조건을 본다. 할 일을 다 수행한 것과 목표를 달성한 것은 다르다. 의미 있는 계약을 마칠 때 이번 결과가 전체 목표의 무엇을 충족했는지만 짧게 연결한다.

평가자는 판정 대상의 분야·합의한 완료 기준·주요 실패 가능성과 현재 증거를 살펴 필요한 검증 방법을 선택한다. 필요한 전문 지식·Skill·원자료·검증 도구를 탐색하고, 현재 환경과 규정에서 허용되는 방법을 활용한다. 실행자가 선택한 방법과 그 검증이 완료 기준을 뒷받침하기에 충분한지도 독립적으로 평가한다.

이미 확보한 유효한 증거를 우선 재사용하고, 완료 판정을 바꿀 수 있는 공백에 추가 검증을 집중한다. 중요도·실패 영향·확인 가능성과 비용에 맞춰 검증의 깊이를 조절하며 모든 작업에 같은 절차를 강제하지 않는다. 기준별 충족·미충족·미확인을 구분하고, 검증 방법의 제안이나 전문적인 설명·다른 AI의 동의를 실제 실행·재계산·원자료 대조의 증거로 대신하지 않는다. 필요한 방법이나 도구를 확보하지 못한 범위는 미확인으로 남긴다. 판정에 이견이 있으면 기준·근거를 대조해 별도 평가자가 다시 판단한다. 남는 객관적 공백은 미확인으로, 가치·수용 기준의 충돌은 사용자 판단으로 연결한다. 같은 기준 안의 결과·증거 부족은 R5에서 보완한 뒤 별도 평가자에게 R6 재판정을 받는다. 사용 중 확인할 항목을 임의의 사전 시험 의무로 바꾸지 않는다.

- **통과:** 이번 범위의 기준이 증거로 충족됐다. 상위 목표나 다음 계약까지 자동 완료하지 않는다.
- **보완:** 같은 기준 안의 결과 또는 증거가 부족하다. 확인된 수행 부족과 증거 공백을 구분한다.
- **재정렬:** 목표·계획·핵심 가정 또는 현재 접근을 계속할 타당성에 문제를 관찰했다. 피벗·보류·중단을 검토할 근거와 영향, 필요한 복귀 단계를 설명하고 사용자 확인을 받는다. 계속되는 위험의 안전 중단은 별개다.

이번 범위의 완료와 현재 접근을 계속할 타당성을 구분한다. 지속 여부를 판단할 때는 단위의 통과·미충족만으로 결론 내리지 않고, R3의 핵심 가정과 R5에서 확보한 근거를 함께 본다.

**출력 순서 — 사용자 선택:** 판정은 **범위·판정 → 기준별 확인 방법·근거·미확인 → 보완·다음 행동** 순서로 전달한다. 객관적 기준은 평가자가 증거로 판단하고 사용자 경험·가치·실사용 확인은 사용자에게 맡긴다. 단순 작업도 같은 판정자 분리를 유지하되 해당 기준만 간결하게 판정한다. 기준이 바뀌면 영향받는 판정만 다시 검토한다.

통과·기록·Skill 호출은 외부 반영, 배포, 프로젝트 인계 또는 새 실행 권한을 만들지 않는다. 현재 유효한 승인 안의 다음 작업은 이어가고 새 판단·권한이 필요할 때만 사용자에게 묻는다.
