# 영향 자료와 관점 갱신

이 참조는 사용자가 자료 추가·관점 교정·스킬 자료 갱신을 요청할 때 읽는다. 일반 분석 요청에서는 필요하지 않다. 사용자가 요청한 저장·정정 범위에서만 수정하고, 이미 승인한 추가·교정을 다시 확인받지 않는다. 단순히 책·영상을 언급한 것을 저장 요청이나 모든 내용의 동의로 해석하지 않는다.

## 새 자료를 추가할 때

자료의 주장과 사용자가 받아들인 방식을 먼저 구분한다. [영향 자료](influences.md)에 아래 내용을 필요한 만큼 남긴다.

- 자료 이름과 출처 성격: 직접 제공한 발췌·요약·자체 작성 해석인지, 원문을 실제 확인했는지.
- 받아들인 내용과 채택 이유: 명시적 동의·선택적 채택·거부·관심만 있는 부분을 구분한다.
- 기존 관점과의 관계: 강화·조건 변경·대체·충돌·새 관점 중 실제 설명이 뒷받침하는 것.
- 적용 분야와 조건: 직접 확인된 사용 범위와 다른 분야로의 확장 가설을 구분한다.

기존 관점으로 표현할 수 있으면 같은 관점을 갱신한다. 판단의 주목·해석·우선순위를 새로 바꾸는 내용일 때만 새 관점을 추가한다. 책·영상마다 새 관점을 하나씩 만들지 않는다. 채택 여부가 없으면 자료를 제공받았다는 사실과 AI의 해석을 분리하고 확인된 신념으로 승격하지 않는다. 방향을 바꾸는 빈칸이 있으면 관련 질문만 묶어서 확인한다.

공개용 자료에서는 관점의 의미·이유·조건과 출처 성격을 남기되 개인 원자료 URL·포인터나 불필요한 개인 사실을 추가하지 않는다. 책명·공개자료·사용자 자체 작성 해석은 개인 포인터와 구별한다. 미포함 개인 자료를 자동 조회하지 않는다.

## 관점을 교정할 때

사용자가 바꾸려는 문장과 적용 조건을 찾는다. 한 사례의 예외인지 원칙 자체의 수정인지를 직접 설명에서 판단하고 중요한 모호성이 있을 때만 확인한다. 한 번의 행동이나 결과로 영구 성향을 만들지 않는다.

수정한 관점과 근거를 함께 맞춘다. 같은 관점이면 의미 중심 제목의 연결을 유지한다. 제목을 바꾸거나 관점을 삭제·대체하면 영향 자료의 링크와 관련 적용 조건도 정리한다. 읽은 순서·영향 시기·우선순위를 알 수 없으면 새로 만들어 넣지 않는다. 사용자가 삭제를 요청한 항목은 본문에 ‘답변 제외’ 같은 대체 설명으로 남기지 않는다.

현재 요청에서 바뀐 판단 기준은 바로 적용한다. 기존 장기 정본의 변경까지 요청한 것인지와 스킬 자료의 교정을 구분한다.

장기 개인 원칙의 정본은 `my-soul` 패키지의 Soul이며 사용자 명시 호출에서만 조회한다. 이 스킬은 영향 자료와 사용자 해석의 연결을 소유한다. 자료를 교정하면서 Soul·Profile·일반 Memory를 자동 수정하지 않는다. 기존 정본 수정이 요청되면 해당 owner의 지침과 정확한 대상에서 처리한다. owner 표기는 책임 범위의 안내이며 관련 스킬이나 개인 자료의 강제 호출이 아니다.

설치본이 원본의 복사본이고 양쪽 변경까지 승인된 경우에는 원본부터 수정해 설치본과 맞춘다. 현재 요청에서 원본·설치 대상이 확인되지 않았다면 파일을 임의로 골라 덮어쓰지 않고 확인된 후보에서 수정안을 준비한다. 후보 작성·검토만 요청받았다면 원본·설치본 수정으로 확대하지 않는다. 여러 원본이나 별도 저장소를 새로 만들지 않는다. 로컬 수정은 commit·push·공유 권한을 부여하지 않는다.

## 근거 추적과 확인

연결은 **사용자 설명 또는 채택·거부 → 영향 자료의 책·직접 설명·공동 설계 주제 → 관점 제목 → 적용 조건**을 따른다. 기준일을 표시할 때는 실제 갱신일을 사용하고 사용자가 확인한 범위와 AI 해석·미확인을 남긴다. 개인화 효과·승률·인구 대비 편향의 수치를 임의로 붙이지 않는다.

수정 범위의 링크·제목 연결·중복·분야 조건을 확인한다. 형식 검사는 판단의 적합성 확인으로 쓰지 않는다. 실제 사용에서 어긋난 사례가 생기면 해당 조건을 좁게 보정하며 작은 문서 수정마다 가상 비교를 다시 수행하지 않는다.
