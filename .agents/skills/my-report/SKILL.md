# 이해 부담을 줄이는 보고서

사용자가 이해하거나 판단해야 할 것을 먼저 정한다. 필요한 내용을 보존하며, 머릿속에서 해야 하는 비교·관계 연결·과정 재구성을 적합한 표현으로 드러낸다.

## 표현과 전달 방식

질문에서 설명 구조를 정하고 글·표·그림의 역할을 고른다. 같은 기준의 항목 비교는 표, 순서와 분기는 흐름도, 포함과 연결은 구조도, 시간에 따른 변화는 시간축이나 그래프를 검토한다. 긴 본문을 완성하고 그림을 덧붙이지 않는다. 형식·분량·그림 수를 고정하지 않는다.

그다음 전달 방식을 고른다. 선택한 표현을 채팅에서 충분히 읽을 수 있으면 채팅으로 제공한다. 넓은 비교 배치, 세부·근거 탐색, 조건·과정을 조작하는 것이 이해를 더 돕는 경우 HTML을 선택한다. 그림이 필요하다는 이유만으로 HTML을 만들지 않는다. 사용자가 지정한 형식은 존중한다.

길이는 보고서가 필요한지 검토할 신호다. 읽기·해석·탐색의 이점과 파일 열기·화면 이동·조작의 부담을 함께 판단한다. 상호작용은 조건 변경, 단계별 과정, 항목과 근거의 연결을 직접 확인하는 이점이 있을 때 사용한다. 질문에 필요한 최소 결과물을 만들고 지속 운영할 앱의 구조를 기본으로 붙이지 않는다.

## 내용 선별과 정보 구성

없어지면 이해·결론·선택이 바뀌는 답, 판단 근거, 조건, 불확실성을 남긴다. 작업 이력과 반복 설명은 질문에 기여할 때만 포함한다. 사실·관찰·해석·미확인을 구분하고 필요한 근거를 설명 대상 곁에 둔다.

질문에 직접 답하는 내용을 먼저 보여준다. 긴 설명은 핵심 답과 주요 항목의 짧은 요지에서 필요한 세부로 이어지게 한다. 요지와 세부는 같은 용어와 순서로 연결하고, 보조 근거는 해당 세부에서 접근하게 한다. 판단을 바꾸는 조건·예외·중요한 불확실성은 기본 화면에서 보이게 한다.

항목 이름만 나열하는 목차를 자동으로 붙이지 않는다. 각 항목의 요지로 전체를 훑고 필요한 세부를 찾아갈 수 있게 한다. 짧은 답에는 별도 목차를 만들지 않는다. 핵심을 알기 위해 모든 세부를 열어야 하는 구성과, 비교할 항목을 다른 탭에 나누는 구성을 피한다.

## 자료 보호

인증정보·비밀번호·API 키·접근/갱신 토큰·세션 쿠키는 본문·그림·HTML·첨부·근거 묶음에 포함하지 않는다. 전체 환경변수나 세션·로그를 통째로 복사하지 않고 질문에 필요한 자료만 선별한다.

필요한 자료에 비밀값이나 불필요한 개인정보가 섞여 있으면 해당 부분을 제외하거나 마스킹한 사본을 사용한다. 사용자 요청에 필요한 개인 자료는 대상 독자와 승인된 범위에 맞춰 보존한다. 원자료를 덮어쓰지 않으며, 첨부와 근거 파일에도 처리된 사본을 사용한다.

전달 전에 본문·HTML 소스·접힌 영역·그림·첨부·근거 파일에 제외 대상이나 마스킹 전 값이 남지 않았는지 확인한다. 화면에서 가리거나 숨기는 것만으로 마스킹이 완료됐다고 판단하지 않는다. 자동 검사나 점수만으로 무유출을 확정하지 않으며, 확인할 수 없는 부분은 전달 대상에서 제외하고 확인 범위를 밝힌다. 로컬 작성은 공유·게시 권한을 뜻하지 않는다. 외부 전달은 사용자 요청과 유효한 승인에 포함된 대상·접근 범위에서 수행한다.

## 글과 그림의 설명 분담

각 그림이 설명하는 주장·관계와 원자료의 근거를 특정한다. 그림은 핵심 설명을 맡을 수 있다. 글을 상자에 옮겨 담는 것만으로 설명 기여를 인정하지 않는다.

그림이 전달한 관계·순서를 본문에서 그대로 풀어 쓰지 않는다. 글은 그림만으로 알기 어려운 의미·이유·근거·예외·불확실성을 보완한다. 읽기 방향 안내와 판단을 바꾸는 조건은 필요하면 짧게 반복한다. 채팅과 보고서에도 설명 전체를 중복하지 않는다.

관련 글과 그림을 가까이 두고 같은 용어·단위·조건을 쓴다. 그림에 직접 레이블과 읽기 방향을 표시하고, 분기·상태의 의미를 색에만 맡기지 않는다. 그림의 핵심 관계를 파악하기 위해 본문 전체를 먼저 읽어야 하는 구성을 피한다.

## 문장

한국어에는 ASD-STE100의 명료성 원칙을 적용한다. 짧고 명확한 문장에 하나의 핵심을 담고 주체·행동·조건을 분명히 한다. 같은 대상은 같은 용어로 부르며 문장 사이의 원인·조건·순서를 연결한다. 간결하게 쓰기 위해 의미나 필수 요소를 삭제하지 않는다. 영어 승인 어휘·단어 수·문법을 한국어에 그대로 강제하거나 규격 전체 준수로 소개하지 않는다. 근거: [ASD 공식 FAQ](https://www.asd-ste100.org/STE_faq.html), [공식 문장 규칙](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf).

## HTML 스타일

HTML을 제작할 때는 [내부 팔레트 안내](resources/palette/README.md)를 읽고 색상·본문 스타일과 확보 범위를 참고한다. 상세 수치와 CSS는 해당 내부 리소스에서 읽고 여기에 중복 보관하지 않는다. 독립 HTML에는 사용한 CSS를 포함해 실행 환경의 로컬 Skill 경로에 의존하지 않게 한다.

사용자 취향 — 모드를 따로 지정하지 않은 새 HTML 보고서는 다크모드를 기본으로 한다. 보고서의 기본 모드를 일정하게 유지하기 위한 기준이다. 사용자 지정 테마와 기존 결과물의 모드를 우선하며, 명시적인 모드 변경 요청이 있으면 반영한다.

본문 읽기 폭과 표·그림·비교 배치의 폭을 구분한다. 좁은 화면에서도 그림의 레이블이 읽히게 배치하고 폭에 맞추려고 글자를 과도하게 축소하지 않는다. 독립 HTML에는 사용한 CSS를 포함해 로컬 스킬 경로에 의존하지 않게 한다.

## 확인과 피드백

사실·관계·수치·조건이 원자료와 일치하고 핵심·판단 근거·불확실성이 보존됐는지 확인한다. 화면 결과물은 실제 표시와 필요한 조작을 확인한다. HTML은 선택한 모드가 실제 화면에 적용됐는지와 한글·좁은 화면의 읽기·탐색도 확인한다. 확인하지 못한 부분을 명시한다.

사용자가 읽기 불편이나 이해 오류를 알려주면 원인을 확인하고 관련 작성 방식을 보정한다. 효과를 비교할 필요가 있으면 같은 질문·자료·공통 조건을 유지하며 부담 체감과 이해 정확성을 구분한다. 반복 읽기의 익숙함과 정보 구성·매체·스타일의 영향을 구분해 해석한다. 지침 사용·검사 통과·외형을 부담 감소의 증거로 대신하지 않는다.
