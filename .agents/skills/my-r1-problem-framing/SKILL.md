# R1 — 문제 구체화

**사용자의 맥락과 근거를 살펴 해결할 문제, 원하는 변화, 중요한 조건을 함께 구체화한다.** 사용자의 관심·가치·우선순위를 탐색의 방향으로 삼고, 제시된 원인과 해결책은 근거에 따라 검토한다. 초기 구상과 제품 형태는 문제 해결을 위한 가설로 다루며, 그 형태의 유지보다 해결하려는 문제와 원하는 변화에 대한 기여를 판단 기준으로 삼는다. AI의 넓은 지식이 사용자가 중요하게 여기는 변화에 기여하도록 문제의 틀을 함께 살핀다. 문제 이해의 합의와 상세 설계의 확정을 구분해, 충분히 탐색하면서 사용자 의도를 조기에 고정하지 않도록 한다.

사용자가 제공하거나 지정한 입력·공유 맥락과 유효한 피드백을 먼저 읽고, 현재 확인·교정을 기준으로 이전 표현을 해석한다. 확인된 사용자 의도와 AI 해석을 구분하고, 해결책으로 표현된 요구도 원하는 변화와 연결한다. 이미 확정한 조건·수단은 보존하며, 반대 근거가 생기면 이유와 영향을 설명해 재검토한다.

새 작업은 여기서 시작한다. 단순하고 명확한 요청은 문제·원하는 변화·중요한 조건을 가볍게 정돈하고 질문이나 별도 보고서 없이 R2로 넘긴다. 비단순 작업이나 명시적인 R1 탐색에서는 사용자의 설명을 되풀이하는 데 그치지 말고, 제시된 원인·해결책의 논리적 빈틈, 중요한 반론과 다른 문제 해석을 검토한다. 참고자료는 그대로 나열하지 않고 문제를 이해하는 데 필요한 개념으로 추상화해 사용자 니즈와 연결한다. 잠정 방향을 설명해 사용자와 같은 문제를 이해했는지 확인한다. 사용자가 R1 탐색을 직접 요청했다면 명확해 보여도 사용자 확인 또는 중단 요청 전에는 탐색을 닫지 않는다.

## 출력 — 사용자 선택

비단순 작업과 명시적인 R1은 **문제 → 원하는 변화 → 지켜야 할 조건 → 방향을 바꿀 미확인** 순서로 제시한다. 사실·가치·원인 가설·수단을 구분하고, 중요한 반대 근거는 이유·대안과 연결한다. ‘원하는 변화’에는 사용자가 제시하지 않은 도전적인 달성 상태·방법도 탐색해, 의미 있는 후보의 효과·필요 조건·부담·미확인을 비교한다. 반복 문제는 운영 방식의 변화도 후보로 살피되, 어려움이나 시스템 변경 자체를 목표로 삼지 않는다. 아직 합의하지 않은 상세 설계·탐색 목표를 확정한 완료 기준으로 취급하지 않는다.

문제·원하는 변화·중요한 조건을 바꿀 미확인은 필요한 조사·질문으로 지금 다룬다. 방향에 영향 없이 구현하며 확인할 사항은 관련 작업으로 넘기고 R1 확정의 선행 조건으로 만들지 않는다. 나중에 확인한 근거가 합의한 방향을 흔들면 영향을 설명하고 사용자와 재정렬한다.

참고자료의 잡음을 덜고 핵심 관계·조건을 추출하는 전문 방법이 필요하면 `my-abstraction`을 활용한다. 결과는 문제 이해에 사용하며 사용자와의 문제 합의는 R1이 맡는다.

합의한 원하는 변화와 중요한 조건을 다음 단계에 전달한다. R2는 세션 목표, R3는 구체 완료 기준과 증거, R6는 실제 수행 결과의 판정을 맡는다. 사용자가 정한 작업 평가 기준이 있으면 대상과 의미를 보존하며, 공통 평가 축의 충족으로 원하는 변화의 누락을 대신하지 않는다. 평가 기준을 문서에 적은 사실과 실제 작업 성과를 구분한다.

같은 작업의 답변·승인·후속 지시마다 R1을 반복하지 않는다. 뒤 단계에서 문제 이해가 달라지면 근거와 영향을 설명하고, 합의한 방향을 바꾸기 전에 사용자 확인을 받는다. R1의 종료는 북극성 목표나 실행 권한의 확정이 아니다. 다음에는 R2가 명시적인 목표 고정이 필요한지 판단한다.

확정한 R1 산출물 전체는 `my-session-save`의 SESSION R1 구획에 원문 그대로 보존한다. 미확정·가설을 확정으로 바꾸거나 단순 요청에 별도 보고서를 강제하지 않는다.
